# 实体场景执行

[English](../en/entity-scenes.md) | [中文](entity-scenes.md)

本文说明各 adapter 如何执行[实体决策](adr-entities.md)定义的公共实体、不可变身份和局部 reset 契约。冷路径 authoring/编译边界见[可移植 MJCF 决策](adr-portable-mjcf.md)。MuJoCo 系 adapter 编译并运行完整场景；Isaac adapter 保留独立 worker 和原生执行。

旧 MuJoCo/MJWarp 编译场景也在冷路径使用相同的 `CompiledModelIndex` audit。它记录原生 body 分区、root、joint qpos/qvel 地址、mocap 地址及 actuator transmission/control 列，不重命名匿名对象，也不把 tendon/site/root transmission 假装成标量 joint actuator。旧 whole-model API 保留源语义；只有分区交叉校验通过时才暴露受限实体布局。

## 源准备与身份

公共 portable MJCF compiler 校验源、默认值、名称、引用资源和同布局 variants，产出 expanded MJCF、冻结的 `CompiledSceneLayout`、source/intent report 与内容身份。独立 worker 资产写入编译器派生的显式 body 惯性参数及关节限位。geometry 名称、body 归属、源 contact mask、源摩擦与 sphere 半径也随 cold-path 意图表传输，并保留每个 body 的源 geom 顺序。单位 gear position drive 意图校验并保存为独立表后，从导出 XML 删除 actuator；原生 MJCF importer 无法安全消费 MuJoCo canonical general actuator 拼写。此 profile 明确拒绝源被动关节 damping/弹簧、activation state、不支持的 transmission 和非标量关节。编译后的逐环境 actuator 控制限位用于 step target 及初始/完整 reset control；未启用限位时不按存储的零范围夹紧。

跨 entity sensor 声明位于场景级、仅含 sensor 的 `fragment_files` 输入，fragment 字节属于 portable identity。Fragment 可声明有序 geom-pair contact 形式或 wildcard body-net contact 形式（省略 `geom2`：对涉及 `geom1` 的所有接触求净力/ found 归约）、使用最终限定名的 world-referenced body/site `FramePos` / `FrameQuat` 形式，或使用最终限定 body/site 名的 world-referenced `FrameLinVel` / `FrameAngVel` 形式；MuJoCo 将其保留在 expanded MJCF 中，mapped IsaacSim 通过 `ContactSensor` 碰撞对 filter 消费 force/netforce contact 形式，并通过批量逐 entity PhysX contact view 消费 wildcard body-net 形式，Motrix 消费经过 audit 的两种 contact 形式、body/site 位姿形式与限定 body/site 运动形式，Genesis 消费经过 audit 的限定 site/body 位姿与运动形式以及两种有边界的跨 entity geom-pair contact 形式。

生成文件名使用安全的内部 USD 标识，不定义公共实体身份。编译后编辑从当前 spec 序列化，避免写出旧编译结果。宿主持有生成的完整场景及独立源，直到 worker 关闭。Worker 返回的实体名称、完整 assignment 和实际实例质量均与编译意图核对。Worker audit 还确认原生拓扑、drive、惯量以及选中的 visual sphere 半径采用情况。Echo 本身不是独立资产身份证据。

耗时的多 variant 构建会在 stderr 上报告进度：场景组合、worker 源导出以及 IsaacGym/IsaacSim worker 初始化在 stderr 是终端时渲染单行进度条。`UNISIM_PROGRESS=always`（或 `1`/`on`/`true`）强制输出，`UNISIM_PROGRESS=never`（或 `0`/`off`/`false`）禁用；默认 `auto` 跟随终端检测。Worker 进度帧仅在宿主通过 INIT payload 主动请求时发送；它们与未完成的 INIT 回复交错传输，并会重置宿主接收超时，因此进度输出不改变协议语义。IsaacSim worker 报告 Kit 启动、跨 variant 物化/原型生成/逐环境拷贝的单一单调 entity 构建进度条，以及直到原生 audit 的 finalizing 阶段。

各 variant 实体场景是彼此独立的 MuJoCo 编译，而编译持有 GIL，因此当绑定声明至少 16 个 variant 时，组合会将它们分发到 `fork` 上下文的进程池（无 fork 的平台回退 spawn）。声明的基准源 bootstrap 实现与所有跨 variant 的 fail-closed 校验仍在调用进程内按 variant 顺序执行，生成的源文件与顺序组合保持字节一致。进程池宽度由 `UNISIM_COMPOSE_WORKERS` 控制（默认 `min(24, cpu_count)`；`1` 禁用进程池）。

Newton 消费 portable compiler 生成的完整逐 variant MJCF，而不使用同构模板复制。它把每个源导入独立的公开 `ModelBuilder`，在每次 `begin_world()` 世界中选择对应源，并为每个物理实体绑定一个公开 `ArticulationView`。冷路径 audit 在构造 solver 前，将每个实际世界的重力、质量、COM、惯性张量、shape 类型和尺寸与选中源逐一比较。此有边界 profile 覆盖每世界多个 articulation 与多个 free root、固定根、被动实体、静态刚体、同布局同 shape 类型的异构 variants 与力响应、局部实体 reset/playback，以及带逐世界归因的具名 geom-pair found sensor。kinematic mirror 与混合 shape 类型 assignment 均快速失败。

Portable Newton 局部 reset 保留无关状态与 control，清空选中实体 control，并对 `restore_default_controls` 快速失败；不声明 keyframe/default control 恢复。

宿主发布独立 nq/nv/nu 和实体根布局。公共 root state 使用 link 原点位置/线速度、wxyz 四元数和世界系角速度；clone offset 由 adapter 恰好消除一次。完整广义 qvel 保留 body 系角速度。被动关节贡献状态，但不隐式增加 action 列。

## Reset 与控制

全部实体 patch 在物化或写原生状态前校验。准备好的行和显式 mask 经同一版本化 reset 命令提交。新实体入口的完整 qpos/qvel 写也归一为相同 patch 提交。完整 `reset()` 恢复选中环境的 variant 默认值和独立 keyframe control；control 不必等于关节位置。其它环境和未选实体保留状态与 targets。

IsaacGym 将 indexed root/DoF 提交累积到下一物理步，避免第二次 indexed setter 覆盖较早 reset。原生 COM 速度在公共 link 原点边界两侧转换。Root 和 joint state 立即可用；初始化或受影响 reset 后的 articulation descendant body/sensor state 在下一 step 前明确不可用。宿主拒绝相关读取，不把旧值当作当前状态。旧 model-file 路径行为不同：PhysX 不推进物理就无法刷新 link pose，因此在 INIT keyframe 或 `set_state` 之后、首个物理步之前，worker 将精确的 MJCF 前向运动学叠加到刚写入的环境上——由有效广义状态计算位置、姿态和 link 原点线速度/世界角速度——并同时清除其陈旧的 contact force 行。宿主把运动学树扫描进 INIT payload（fixed variants 下逐 variant），与公开 body/joint 布局不一致时 fail-closed。legacy reset 输入遵循 canonical 广义速度约定（世界系 link 原点线速度、body 系角速度）；历史 COM 速度投影仅保留在对外发布的 legacy 输出缓冲上。

mapped IsaacGym 的 `set_state()` 局部行接受既有 `ResetRandomizationPayload`，覆盖 actuator `kp`/`kd`、`body_mass`、`body_ipos`、`body_inertia`、`dof_armature`、`dof_frictionloss` 与 Coulomb `geom_friction` 写入。宿主在任何原生修改之前预校验精确的公共形状、有限值、正性、浮动根 DoF 列为零，以及 friction 的 `static == dynamic` 与第三列精确为零约束。worker 随后快照全部原生属性表，在写入暂存状态之前通过 actor DoF、刚体与形状属性 setter 应用修改，读回所有表，并审计选中行符合请求且未选中行不受影响；不一致会使 worker fault，只有通过校验的读回才提交进 worker 记录与 native-root 速度换算依赖的 body/root COM 缓存。`body_inertia` 行是与所分配 variant 惯性姿态复合成 PhysX 惯性张量的主惯量三元组。`gravity` fail closed，因为 PhysX 重力是仿真全局量而非局部环境状态；`dof_damping` fail closed，因为 PhysX 没有独立于导入 position drive 的被动关节阻尼通道；base mass/COM delta、惯性姿态、geometry 尺寸与 contact solver 参数同样 fail closed；legacy model-file 路径在修改前拒绝所有 randomization 项。

mapped IsaacGym 还在宿主以 `(num_envs, nbody, 6)` 表暂存世界系 `body_force`/`body_torque` 区间 wrench。STEP 命令携带暂存字节；worker 通过经过审计的 actor body 索引把公共 body 行 scatter 到 env 局部 `ENV_SPACE` force/torque tensor，并在每个请求的子步前用 `apply_rigid_body_force_tensors` 重新施加，因为 PhysX 每次 simulate 后都会清空外力。力作用于 body COM；原生 setter 失败会使 worker fault，格式错误或非有限 payload 在 step 前被拒绝。

无法恢复的原生提交失败会设置 worker fault 标记，宿主拒绝后续状态和 step 使用。提交前校验失败保留会话。共享内存槽在 attach 前校验 shape/dtype，包括零宽动作或状态布局。

## 检查与回放

Worker 必须提供版本化配置报告，宿主校验后才接受。实体 assignment、body mass 与 geometry 使用作用域记录，区分源意图与实例读回；源值不替代缺失的运行值。mapped IsaacSim 场景中，INIT 会校验原生 mass、COM 与 geometry 记录；`get_body_mass()` 再将这些 worker 原生快照 scatter 到冻结的公共 body 顺序，返回独立的 `(num_envs, nbody)` 表。未被实体拥有的公共行保留编译源规范值；reset 时的修改随后会替换相应的当前行（见下文）。`get_body_ipos()` 返回形状为 `(nbody, 3)` 的独立编译源规范默认值；`get_body_ipos(env_ids=...)` 返回形状为 `(len(env_ids), nbody, 3)` 的 worker 原生物化行，并保留空选择、重复项与乱序选择。公开 geometry 按冻结的 entity/geom 记录排序：`get_geom_names()` 返回具名地址，`get_geom_body_ids()` 返回公共归属 body ID，`get_geom_contact_masks()` 将原生 collider 启用状态规范化为一对相同的 contype/conaffinity 行，`get_geom_friction()` 返回形状为 `(num_envs, ngeom, 3)` 的独立 worker 原生 PhysX material 行，格式为 `[static, dynamic, 0]`。初始 material 随不可变 variant assignment 变化；局部 reset 可以替换当前 material 行，普通状态 reset 不会隐式恢复它们。collision 状态仍由 role 决定且不可变。worker 从实际 spawn 的 collision prim 读取身份与 material，并拒绝数量、名称、归属、mask 或 material 漂移。独立的 visual `Sphere.radius` audit 仍是有边界 sphere profile 检查，不是尺寸 API。

mapped `set_state()` 使用既有 `ResetRandomizationPayload` 支持局部环境的属性写入。支持的项包括：正 `body_mass`、`body_ipos`、正对角 `body_inertia`（惯量主轴姿态保持该环境不可变的 assigned-variant `body_iquat`）、Coulomb `geom_friction`、actuator `kp`/`kd` 驱动增益，以及非负的 `dof_damping`/`dof_armature`/`dof_frictionloss` 关节表；`base_mass_delta`/`base_com_offset` 在 host 侧折叠进主实体根 body 行。正值约束仅作用于实体拥有的行：未被实体拥有的 world body 行携带零 canonical 占位值并保持 pinned。每张表都是按冻结公共列顺序排列的绝对 dense 公共布局表且必须有限；friction 要求非负且满足 `static == dynamic`、第三列精确为零；free-root DOF 列必须保持为零，因为 PhysX 不暴露 root 关节 damping/armature/friction。kinematic mirror 实体拥有的列或不属于任何实体的列必须等于其 variant 或规范默认值。该命令复用 `RESET_ENTITIES`，通过映射后的公共 PhysX view 写入（rigid-body mass/COM/inertia view、逐行 articulation 驱动与 DOF setter、material view），写后读回原生值，对照请求校验选中行、对照写前快照校验未触碰行，刷新宿主当前值 getter；原生写入/读回失败会使 worker fault。驱动 `kd` 与自然 `dof_damping` 加性组合进 PhysX 唯一的关节 damping 槽位；worker 同时跟踪两个通道，保证重复 reset 保持精确。gravity 保持不支持，因为它是仿真全局量而不是局部环境状态；惯量主轴方向、geometry 尺寸与 solver contact 参数带逐项显式理由 fail closed。版本化 import report 描述 materialization，不能当作 reset 后的当前值读回。回放返回选中环境的完整场景源，保留 robot、object、table 和 mirror。原生渲染仍由 worker 拥有；本切片尚未提供 mapped worker 的 physics snapshot 导出。

当前原生相机 profile 使用既有跟踪行为，拍摄环境 0 的第一个实体。录制只支持配置 `cam_distance`、`cam_elevation` 和 `cam_azimuth`。非默认的 `cam_lookat`、`cam_tracking`、`cam_tracking_env_idx`、`cam_tracking_extra_envs` 或 `cam_fov` 在访问 worker 前抛出 `NotImplementedError`，重复初始化 renderer 时也会校验。默认 `CameraCfg` 保留既有原生视图，不会选择 MuJoCo 网格相机。交互 viewer 也拒绝自定义球面偏移，其视图由原生 viewer 控制。可以返回任意选中环境的完整场景源，不代表原生相机可以选择该环境。

IsaacSim 将不可变 assignment 映射为 K 个唯一原型，并把选中的原型复制到每个精确环境路径。assignment 在 construction 固定，reset 不重采样。各 variant 必须共享同一公开布局以及相同的 effort limit、armature 与关节摩擦，但驱动 stiffness/damping（`kp`/`kd`）可按 variant 不同：初始化通过逐行 PhysX view setter 为每个环境重写其 assigned variant 增益，post-init audit 会按环境对照 assigned variant 校验原生增益。实体绑定的 `uniform_public_layout` catalog 还允许各 variant 省略可选 mesh-geom 槽位：由于 IsaacSim 把所有环境放进同一个同质 PhysX view，role bake 会为每个被省略的槽位补一个禁用碰撞、不可见的微小占位 sphere，并预写身份属性（role USD 缓存身份会跟踪这些参数）；原生 geometry 的写入与读回按这些属性匹配 prim，而不依赖子节点顺序；宿主 audit 只接受 assigned variant 省略该槽位的环境上报全禁用占位行。单 body rigid view、固定根模式、环境 view 行映射、mass/COM/惯量以及选中的 visual sphere 半径均独立 audit；拓扑、drive 与源格式限制仍 fail closed。共用宿主只启用已说明的 MJCF 标量关节 profile，不代表 URDF 或全部 PhysX 资产特性。

映射 IsaacSim 场景兑现每个启用碰撞的 articulation 实体的 `self_collision` 声明。宿主在 worker 实体记录中转发该标志；worker 将其同时纳入 raw USD converter 参数与缓存身份，通过 MJCF converter 应用，并审计每个 spawn 实例上的 `physxArticulation:enabledSelfCollisions` 标志。固定根 articulation 在 role bake 时会把 PhysX articulation API 移到外层根 prim，因此校验过的标志会在那里显式重写。源中声明的 MJCF `<contact><exclude>` 对与该标志无关，始终保持排除（importer 将其烘焙为 USD filtered pairs，且 PhysX 对直接由关节连接的 link 对永不碰撞）；rigid 实体、mirror 和禁用碰撞的实体完全不能请求自碰撞。worker 在版本化配置报告中按实体上报有效标志，宿主将该报告与 INIT 请求严格比对。MJCF 原生后端保留源声明的自碰撞行为，并对逐实体开关 fail closed。

映射 IsaacGym 场景通过 PhysX 碰撞过滤器编写而非 articulation 标志兑现同一开关。PhysX 恰好在两个 shape 的过滤字共享一个比特时抑制接触对，而映射 profile 已为每个启用碰撞的实体分配一个比特用于实体间过滤（副作用是禁用 actor 内部接触）。请求自碰撞的实体改为以零 actor 过滤器 spawn，随后 worker 通过 rigid shape 属性为每个带碰撞 shape 的 body 分配一个互不相同的逐 shape 过滤比特，并通过原生 shape 属性读回校验这些值：该 actor 的不同 body 之间没有共享比特因而可以碰撞，其他物理实体保持逐实体比特方案不变，禁用碰撞的 actor（包括 mirror）携带所有已分配比特的并集，因而仍与这些 body 保持排除。有两类限制因共享比特方案无法表达而 fail closed：自碰撞实体上源声明的 `<contact><exclude>` 对（它们需要逐碰撞对的比特着色，而静默升级为完全自碰撞会违反"精确兑现或拒绝"契约），以及实体比特加逐 body 比特超出 30 比特过滤器预算的场景。无论过滤器如何设置，PhysX 对直接由关节连接的 link 对永不碰撞。worker 在版本化配置报告中按实体上报有效标志与 body 比特分配，宿主将该报告与 INIT 请求严格比对。legacy model-file 场景保持自碰撞关闭。

映射 IsaacSim 与 IsaacGym 场景兑现每个实体的 `gravity_disabled` 声明。`None`（默认值）保留各后端既有的隐式逐实体行为：IsaacSim 对 kinematic 实体和固定 rigid body 关闭重力，IsaacGym 则对每个实体资产保持重力开启。显式 `True`/`False` 必须被精确兑现或拒绝，绝不忽略：宿主在 INIT 前把解析后的值写入 worker 实体记录，凡是没有 exact `entity.gravity_disable` 声明的后端都在组合协商处 fail closed。IsaacSim worker 按解析值烘焙 `physxRigidBody:disableGravity`，并在每个烘焙或缓存命中的 role 上重新校验；IsaacGym worker 在资产加载时设置逐实体 `AssetOptions.disable_gravity`，因为 IsaacGym 没有逐 actor 的重力读回。两个 worker 都在版本化配置报告中按实体上报解析后的标志，两个宿主都将该报告与 INIT 请求严格比对。

IsaacSim 缓存两个不可变冷路径 USD stage。Raw cache 在 `~/.cache/unisim/isaacsim/raw-usd` 下保存 expanded MJCF 到 raw USD 的转换输出；可将 `UNISIM_ISAACSIM_RAW_USD_CACHE` 设为绝对路径，或使用只读兼容回退 `UNILAB_ISAACSIM_RAW_USD_CACHE`。Raw identity 在 portable scene content identity 之上追加 expanded source digest、importer 参数、IsaacSim/IsaacLab/MJCF importer/Python 版本、实体和 variant。Role cache 在 `~/.cache/unisim/isaacsim/role-usd` 下保存独立 bake 的 USD；可将 `UNISIM_ISAACSIM_ROLE_USD_CACHE` 设为绝对路径，或使用只读兼容回退 `UNILAB_ISAACSIM_ROLE_USD_CACHE`。空值或 `0`、`false`、`no`、`off`、`none`、`disabled`（不区分大小写）会独立禁用对应缓存。Role identity 在 raw identity 与不可变 raw artifact 指纹之上追加 source/role 实体、variant、kind、root mode、collision/mirror 设置和 bake 参数。命中会校验完整 manifest、文件清单、大小和 SHA-256；转换与 bake 输出先写入 staging 再原子发布，格式错误、中断或损坏条目按 miss 处理并替换。Role miss 会先复制完整 raw artifact 再 bake。Role hit 会重新读取 variant 元数据、native body path、articulation/rigid 拓扑、mobility、gravity、collision 和已禁用的 converter drive，然后才执行原生 materialization、prim/view 构建、参数读回、capability 检查和 effective-report 校验。禁用 role cache 时仍会为每个 role 生成独立临时副本，因此 role 编辑不会修改缓存 raw USD 或另一个 role。运行时 PhysX solver 设置（solver 迭代次数、bounce threshold velocity、contact offset、rest offset、max depenetration velocity、GPU rigid contact/patch 缓冲容量）不会进入任一缓存 identity：它们不改变被缓存的 USD artifact，而是通过 worker 的版本化 configuration report 进行校验。

映射 IsaacSim 场景通过 PhysX contact reporter 服务两类 contact 查询。声明 `<contact data="force" reduce="netforce" geom1="..." geom2="..."/>` 碰撞对时，每个 pair 使用一个 filtered IsaacLab `ContactSensor`：数值单位为牛顿，是世界系 3 向量，表示 `geom2` 目标 body 作用在 `geom1` 来源 body 上的 filtered normal contact force，由 IsaacLab 对接触点求和。省略 `geom2` 即声明 wildcard body-net 形式：worker 为每个被引用 entity 打开一个批量、无 filter 的 PhysX `RigidContactView`（显式逐 body pattern，因为烘焙后的 USD 按运动学深度嵌套 body），将 `get_net_contact_forces()`——每个 body 受到的、来自任意接触对象的净接触力——发布到共享的逐 body 槽位。body-net `data="found"` 声明把同一逐 body 净力归约为 0/1 接触标志（模长大于零）。`get_sensor_data()` 返回最后一个已完成物理子步，不在子步间平均；无接触的 pair/body 返回零，reset 清理陈旧行。两种形式都报告 PhysX 净法向力（不含切向摩擦）且绝不得混入自接触，因此 `self_collision=True` 实体上的同实体 pair 与 body-net 声明均 fail closed；PhysX 符号约定（作用在 `geom1` 上的力）与 MuJoCo 原生 contact sensor 拼写（`geom1` 施加给对方的力）相反，但模长一致。未支持的 reduction 以及 legacy model-file 场景上的一切 contact 声明均快速失败。SDK-free 测试固定声明、wire、行映射和 reset 语义；gated real-worker 套件检查 pair 与 wildcard body-net 两种形式下 1 kg 与 2 kg 的静态支持力、found 标志以及选中 reset 行的清除。

Mapped IsaacSim 还支持作用于原生 body COM 的世界系 `body_force` 与 `body_torque` 区间 wrench。多次提交在下一次 step 前累加，作用于请求的每个子步，并在随后消费。Entity reset 清理选中实体 body，完整 reset 清理所有暂存 body 行。映射场景也接受既有宿主 `set_pre_step_control()` callback：宿主把一个公开子步对应为一次 worker STEP，并在每次 callback 前刷新共享状态。callback 的 control 与动态 wrench 每个子步从头重算，与暂存区间 wrench 叠加，并在 step 调用结束时消费。这是正确性宿主循环，不是 #152 跟踪的 device-resident controller 或性能路径；legacy model-file callback 仍不支持。

## Drake 有边界 portable profile

Drake 消费公共 portable compiler 产出的 expanded MJCF，并只在 DrakeUni 公开 model 信息与 body 查询和冻结的 `CompiledSceneLayout` 完全一致时接受布局：维度、全局 body 名称/ID、每个 root 与标量 joint qpos/qvel 映射、joint 全量消费、actuator 名称顺序及目标地址都必须精确绑定。固定 root 通过公开 body-state 查询读取；浮动 root 使用广义状态快照。被动关节贡献状态与速度，但不隐式增加控制列。

局部 entity reset 先快照完整场景状态，应用已校验 patch，再通过 DrakeUni 公开 reset 提交完整、一致的行为。未选中的实体与环境保留状态。原生 reset 失败会使 backend 进入 faulted。`restore_default_controls=True` 会在变更前被拒绝，因为 DrakeUni reset 尚未提供显式 control 恢复契约。entity 模式同样拒绝隐式单 root base/body-frame 辅助接口。

此 Drake profile 支持无 variant，以及带固定/浮动 root、被动标量关节和固定 rigid 静态实体的同布局 fixed variants。无 variant 场景使用一个 expanded portable model；fixed-variant plan 为每个**实际使用**的 variant 创建一个 DrakeUni runtime，并只分配该 variant 的公开环境行。step、reset、sensor 与 body-state 流量都会在公开行和局部行之间显式 scatter/gather。使用的 variants 必须保持相同 control 与 sensor 元数据；暴露 backend 前，构造路径会比较 joint/actuator 地址、控制限位、范围、增益、sensor 与维度。

Fixed-variant 验收以 DrakeUni 公开 `native_model_properties()` 的实际读回为准：body 顺序、质量、COM、body 原点惯量、collision geometry 顺序/归属/类型以及原生 primitive 参数必须在严格容差内匹配对应编译源。未支持的 primitive 身份、mesh/convex 身份、kinematic mirror、其它 variant layout 与 `restore_default_controls=True` 均快速失败。多 variant plan 的 `get_playback_model()` 必须显式给出 environment index，并返回该行不可变的生成模型。不声明吞吐优化。

Drake 原生验收是支持声明的必要条件；缺少 Drake native batch extension 时可选测试会跳过。DrakeUni 必须同时包含多实体布局排序修复和公开 native model-property 读回。当前发布的 `drake-uni==0.1.0` 早于这些前置，普通 CI 也不提供原生 Drake 证据。

## Genesis 有边界 portable profile

Genesis 以公共 portable compiler 作为布局、身份、来源与来源关系的权威。适配器通过公共 loader 归一化每个源，序列化为 Genesis 独立持有的 MJCF 输入，并把每个公开实体分别加入同一个原生 `Scene`。物化时，物理实体只有在原生状态维度、实际 link 名称、原生惯量矩阵、joint 地址、actuator 顺序和 PD 增益与独立编译源一致时才被接受；绑定绝不假设 Genesis link 顺序。公开 qpos/qvel、body 和 actuator 列随后 scatter 到所属实体，被动实体贡献状态但不产生控制列。物理来源的关闭碰撞 mirror 使用 Genesis 公开 `Kinematic` material 物化：其拓扑与 fixed-variant visual 身份仍被审计，但 qpos/DoF 为零且不拥有 collision geometry，因此不为 mirror 声明物理惯量或质量身份。

首个 profile 覆盖固定 root articulation、浮动被动 articulation、浮动异构 rigid object、固定 rigid 静态实体，以及物理来源的关闭碰撞 visual mirror。异构 variants 仅支持单 link rigid 实体。由于 Genesis 1.3.3 会自行分配 MJCF morph 可迭代对象，构造只接受与该原生行为一致的精确公共 balanced mapping——K 个 variant 在 N 个环境中按连续块分配，前余数个块各多获得一个环境。N5/K2 对应 `[0,0,0,1,1]`；`[1,1,0,1,0]` 会在构造 Genesis scene 前被拒绝。该 owner 侧映射校验独立于 Genesis 私有 solver 辅助函数。

构造会从每个规范化 source 冻结 portable 默认值。配置的 `default_keyframe_name` 若能在某个 source 中解析，则只通过公共的逐 entity Genesis API 覆盖该 source key 的标量 hinge/slide qpos/qvel 与 actuator control。若 source 缺少所选 key，则保留其规范化标量 qpos，并保持 qvel/control 为零。原始 source-keyframe root 位姿与速度被忽略：保留声明的 portable 原生构造 root 放置，默认 root 速度保持为零。Genesis 1.3.3 没有持久公共 control-target getter；冷默认表与公共提交路由就是验收边界。

局部 `set_state()` 与 `reset_entities()` 只把选中行提交到所属原生实体，保留未选中的实体与环境。部分原生状态提交失败会使 backend 进入 faulted。局部 entity reset 中，`restore_default_controls=False` 清空该 entity 的选中 control 行，`restore_default_controls=True` 恢复其按 assignment 解析的默认 control 列；无关行与实体保持不变。Portable 选中行 reset randomization 仅覆盖 `body_mass`、`base_mass_delta`、`body_ipos`、`base_com_offset`、`dof_damping`、`dof_frictionloss`、`dof_armature` 与 actuator `kp`/`kd`：公开列先完成预校验，再通过审计后的所属实体拆分，并使用公共原生 setter 提交；部分原生失败会使 backend 进入 faulted。mass 与 COM 通道彼此独立，公开绝对 COM 会先减去不可变 variant-assigned 默认值，再转换为 Genesis 局部 COM shift。其他 reset-randomization 项与 reset 时 body-force 映射快速失败。选中 mirror root 是 state-only 语义：公共世界系 `set_pos(..., envs_idx=...)` 与 `set_quat(..., envs_idx=...)` 提交选中位姿行，完整 reset 恢复各自独立声明的默认值。mirror 的质量、惯性、COM/DOF/actuator 修改和 body wrench 没有原生物理归属，均快速失败。物理（非 mirror）kinematic 实体与 legacy 单主实体 DoF 视图仍不支持。声明的固定/浮动 root 世界放置通过公共 MJCF morph position/quaternion 参数传递，因为该导入路径中原生 Genesis 不会把归一化 root placement 保留为 free-joint 默认值。

Portable geometry 暴露冻结的限定名称、公开 ID、归属 body ID、有边界的 Genesis 原生 geometry 尺寸、contact mask、摩擦系数与 contact solver 参数。构造会按名称、归属 link、精确 active environment 行以及已审查的源 AABB 边界审计每个源 variant 的具名原生 visual instance；当前 visual 身份仅支持 sphere 与 box，不支持的 geometry 类型和模糊或缺失的原生身份都会快速失败。Geometry 尺寸从这些已审计的原生 AABB 派生：sphere 暴露原生半径，box 暴露原生 half-extent，并按冻结公开顺序聚合；非一致 fixed-variant 尺寸快速失败。`get_geom_contact_masks()`、`get_geom_friction()`、`get_geom_solref()` 与 `get_geom_solimp()` 只按名称、归属 link 与 active environment 行把完全匹配的 collision instance 聚合到冻结公开顺序。visual mirror 从其物理/碰撞豁免的公共 Kinematic 边界贡献公开零 contact mask，但没有可用于摩擦、solver 参数或 contact fragment 的原生 collision 身份。mask 是 Genesis 重新编码后的原生值，不是 MuJoCo 表的回显；摩擦列按 Genesis 公开原生系数顺序 `[sliding, torsional, rolling]`，不是 static/dynamic material 表。Genesis 的原生七值 solver 表在公共边界拆分为 MuJoCo 兼容的 `solref = [timeconst, dampratio]` 与 `solimp = [dmin, dmax, width, mid, power]`；因此 importer 预处理或默认值以实际原生值报告，而不是回显源 XML。这些是构造期属性读取，不声明 reset 修改或 solver 功能启用。缺失或模糊的 collision 身份，以及非一致 fixed-variant mask/摩擦/solver 参数，均快速失败。其他 geometry 属性仍不支持。每个物理来源的原生 link 惯量矩阵会对照编译出的对角惯量和姿态，但不暴露任意惯量读回。异构惯量记录加 free-body 响应提供有边界原生证据；由于验收 variants 的质量、COM 与半径也不同，该响应并不能单独隔离惯量影响。

原生 variant 质量通过公共 Genesis mass getter 读取并 scatter 到冻结公开 body 行；带选中环境的 `get_body_ipos(env_ids=...)` 暴露逐 variant COM 行，而无参数 `get_body_ipos()` 仍返回规范的 `(nbody, 3)` 默认表。成功的 mass 或 COM randomization 会在全部原生提交完成后才更新对应的逐行有效 host cache；source/variant 默认值仍是随机化基线，而不是上一次随机化值。Genesis 1.3.3 通过公共 `RigidEntity.set_COM_shift(...)` 暴露 COM mutation，但没有 entity 级 COM-shift getter，因此运行时边界是审计后的 setter 加 host cache；原生 solver 读回只作为显式测试证据，backend 运行代码不依赖它。

Portable DOF 读回通过已经审计的 joint/native qvel 地址映射暴露 Genesis 公开的原生 `get_dofs_damping()`、`get_dofs_frictionloss()` 与 `get_dofs_armature()` 表。构造期捕获所有 active-environment 行，同一个 fixed variant 内的非一致行会被拒绝；只有所有 fixed variants 一致时，公开 DOF getter 才返回一份分离的冷默认 `(nv,)` 表。选中行 reset randomization 会把精确 `(rows, nv)` 公开表路由到所属实体的公共 `set_dofs_damping(...)`、`set_dofs_frictionloss(...)` 与 `set_dofs_armature(...)` API；原生公共读回只作为验收证据，无参数 backend getter 仍返回冷默认值，而不是每环境当前值镜像。被动关节 damping、friction loss 与 armature 仍区别于导入的 position-drive `kp`/`kv`，且不声明恢复。

Portable source sensor 仅接受 entity 内、未引用参考系、且 accelerometer 为 identity 局部姿态的 site `framepos`、`framequat`、`gyro`、`velocimeter` 与 `accelerometer` 声明。site 必须具名、属于同一个公开 entity、使用类型要求的维度，并在所有 fixed variants 中保持完整 sensor 身份一致；公开名称会添加 owner 前缀。Genesis 不导入 MJCF sensor，因此 pose/motion 行由公开原生 link 状态加上已审计的 site 局部位姿计算：pose getter 提供 source/user body frame，公开 velocity getter 提供世界系 link-origin 运动。Accelerometer 会在已审计的 entity/link/site offset 上创建一个干净的公开原生 IMU；其 proper linear acceleration 是已完成 step 的原生 sensor 读取，而不是状态提交时合成的结果。公开 `framequat` 使用 Genesis/MuJoCo 兼容的 wxyz 顺序。引用参考系、旋转 accelerometer、contact sensor 与其他所有 source-sensor 形式均快速失败。

场景级限定 site fragment 仅接受指向最终限定公开 site 名称、world-referenced 的 `framepos`、`framequat`、`framelinvel` 与 `frameangvel` 声明。其完整 site 身份必须在每个组合 fixed variant 中一致；位姿读取使用与 entity 内 site 位姿 sensor 相同的公开原生 link/source frame 和已审计 site 局部位姿计算。`FrameLinVel` 是世界系 site 点速度（公开原生 link-origin 线速度加上世界角速度与旋转后 site offset 的叉积），`FrameAngVel` 是公开原生世界系角速度。该世界系结果有意区别于 entity 内 `velocimeter`/`gyro` 在已审计 site 坐标系中的读数。引用形式、site accelerometer、entity 内 frame-motion 声明与其他所有 site fragment 形式均快速失败。

场景级 body frame fragment 仅接受指向自身精确最终限定公开 body、world-referenced 的 `framepos`、`framequat`、`framelinvel` 与 `frameangvel` 声明。MuJoCo body frame sensor 返回 inertial body frame，因此 Genesis 会把审计后的公开原生 link-origin 位姿与按 assignment 选择的源 body inertial 位置/姿态组合。运动读取使用公开原生世界系 link-origin 线/角速度：`FrameAngVel` 直接返回角速度，`FrameLinVel` 用世界角速度与旋转后源 `body_ipos` 的叉积计算 inertial-frame origin 速度。fixed variants 必须保持完整 body sensor 身份；源 inertial 元数据提供逐 variant inertial identity。entity 内 body sensor、引用形式与其他所有 body fragment 形式均快速失败。Genesis 的原生惯量 audit 也会拒绝源 inertial 姿态不匹配，而不是返回错误参考系的 body frame。

场景级跨 entity geom-pair contact fragment 仅接受 `data="found" num="1"` 与 `data="force" reduce="netforce"` 声明。Genesis 会按名称、归属 link 与 active-environment rows 把每个公开 geom 绑定到精确原生 collision instance，按 fixed-variant assignment 路由这些 ID，并把 Genesis 公共批量 `get_contacts()` 的 geom ID 与 valid mask 作为无序 pair 匹配。found 标志描述最近一次已完成物理 step。netforce 读取公共 `force_a`/`force_b` 张量，按精确原生 geom 顺序选择作用在作者声明 `geom1` 上的力，对所有精确匹配的有效 contact slot 求和，并返回已完成 step 时 `geom2` 作用在 `geom1` 上的世界系 3 向量；选中 state/reset 行在下一次完成 step 前保持为零。同 entity pair、source contact sensor、缺失或模糊的 collision 身份以及其他所有 contact 形式均快速失败。

Portable `apply_body_force()` 会把每个审计后的公开 owned-body ID 映射到所属实体的全局 Genesis solver link。公开 world/未归属 body `0` 仅用于布局一致性，作为 wrench 目标会被拒绝。力与力矩是世界系向量，通过公共 `RigidSolver.apply_links_external_force(..., ref="link_com", local=False)` 与 `RigidSolver.apply_links_external_torque(..., ref="link_com", local=False)` API 提交；力作用在目标 link COM。重复 direct 提交与同一 interval plan 内的 op 会为即将到来的原生 `Scene.step()` 按通道独立加性累积；Genesis 会在该 solver 调用的所有内部 substep 中应用这些 wrench，并在结束时清除原生 external force/torque。backend 只会在物理 substep 成功后清空 pending host 记账。后续 interval plan 会先取消之前的 pending 暂存，局部 `set_state()` 行会取消这些行的所有 pending body，局部 `reset_entities()` 行会取消每个所选实体拥有的全部 body，同时保留无关 pending wrench。原生提交或取消失败会使 backend 进入 faulted，callback 内暂存会被拒绝。不支持任意作用点、动态 callback wrench 与 reset 时 body-wrench randomization。

## Motrix 有边界 portable profile

Motrix 通过公开 `msd.from_file()` 与 `msd.build()` 导入公共 compiler 生成的完整 expanded 多 root MJCF。构造时，只有实际 Motrix 元数据与冻结的 `CompiledSceneLayout` 一致才接受 entity mode：qpos/qvel/actuator 维度、原生 link 名称、浮动 root 与标量 joint 状态地址、完整广义状态顺序、actuator 名称/顺序/目标以及 geom 名称/顺序都必须一致。Variant context 还会审计原生 body/geom 顺序、公开 control 与 joint limit、actuator 增益和 geom 摩擦，捕获实际原生 geometry 尺寸，并读回构造 mass/COM。公开 body 与 geom ID 通过这些审计后的原生映射 scatter，而不是假设 Motrix link 或 geom 顺序。

首个 profile 覆盖无 variant 与不可变 same-layout fixed-variant 的固定/浮动物理实体、被动标量关节、固定 rigid 静态实体和关闭碰撞的 kinematic mirror root。Motrix 为每个被使用的 variant 创建一个原生 model/data context，并按不可变 assignment 显式 scatter/gather 公开 qpos/qvel、control、局部 reset 行、step 执行和 link pose/velocity 行。运行前变更发生前，每个 context 会捕获原生构造 control；若配置 `default_keyframe_name`，则捕获唯一同名原生默认 keyframe 的 `ctrl` 记录，并按已审计的原生 control limit 截断。构造 forward-kinematics 之前，它还会通过 `Keyframe.apply()` 应用所选 keyframe 的公开 `dof_pos`/`dof_vel`，使该 key 状态成为 context 的构造/完整 reset 默认值。Variant geometry、mass、COM 与惯量可以不同；`get_body_mass()` 暴露逐环境原生行，带选中环境的 `get_body_ipos()` 暴露原生 COM 行，审计后的原生 geometry 记录保留实际逐源尺寸。Motrix 不提供惯量读回，因此原生验收对被动标量 joint 施加相同 torque 并验证不同的有效响应，而不是假装存在 getter。它也不提供 actuator activation state，因此带 activation 的 portable 场景会快速失败，而不是把 activation 静默清零。非一致的公开 control/joint limit、actuator 增益或 geom 摩擦会快速失败，因为公开 API 暴露规范标量表。`apply_body_force()` 通过审计后的公开 `Link` API，把世界坐标 public body force 与可选 body torque 行映射到每个拥有它的 variant context：提交会为即将到来的原生 step 加性累积，并在该 step 消耗；局部 root/joint reset 只取消受影响 entity 的 body 行，无关 pending wrench 保持不变。缺失任一所需原生 API 时快速失败。

Motrix 还接受 MotrixSim Core 0.10.1 上一组有边界的 `uniform_public_layout` profile，用于完整存在的 mesh slot。冷路径会把每个受影响的公开 mesh geom 映射到原生 mesh variant set，candidate 顺序遵循 fixed-variant ordinal 顺序，然后为所有环境使用一个规范原生 `SceneModel` 与一个批量 `SceneData`。构造时会审计逐行 `Shape.Mesh` override 与精确的原生 mesh ordinal 读回，并且选择在 reset 与物理 step 后保持。Optional 缺失 mesh slot 以及任何非 mesh 的物理、材质、geometry 或惯量差异都会快速失败，因为该 profile 只允许共享原生模型中的 mesh identity 变化。原生 renderer 会接收选中的逐行 mesh identity 与已审计 render offset，因此该有边界 profile 声明逐环境 playback。Same-layout variants 继续使用独立的按使用 variant context，并保留原生 playback 快速失败边界。

Mirror root 必须物化为公开原生 mocap body。构造会跨 fixed variant audit 完整 mirror body/mocap 身份，并要求每个导入 mirror geom 的公开 collision group 与 affinity 均为零。选中行的 mirror 位姿写入会把公开 wxyz root 转换为 Motrix xyzw mocap 位姿，并通过所属 variant disjoint 数据切片上的公开 `Mocap.set_pose()` 提交；无关行与实体保持不变。完整选中环境 reset 会恢复 mirror 独立声明的默认位姿。物理（非 mirror）kinematic 实体仍不支持。

当 `add_body_sensors=True` 时，Motrix 会在 variant 物化前把 `base_name` 解析到冻结的公开 body 布局：限定名 `entity/body` 必须精确匹配，本地名必须唯一匹配一个公开 body。随后每个原生 variant 会为所有公开 body 生成 Motrix frame-position 与 frame-quaternion sensor。构造要求每个公开 body 恰好两个 sensor、各 variant 名称完全一致，并校验原生行数和维度。公开 sensor getter 按不可变 variant assignment 从所属 context gather 行；batch 读取按请求顺序展平并拼接每个 sensor。`get_sensor_data()` 保持原生 xyzw 四元数，`get_body_quat_b()` 转换为公开 wxyz 约定。局部 reset 会刷新派生 frame sensor，但不会提交无关广义状态行。

Authored source 与场景级 fragment frame sensor 仅接受 public body 或唯一限定 public site 上的 world-referenced Motrix `FramePos` / `FrameQuat`。entity-owned source 名称保留 owner 前缀，且只能指向同一 entity 内的 site；fragment 名称不带前缀，并指向最终 public body/site 名称。公共 compiler 会跨 variant 冻结其公开名称、类型、维度和对象引用；Motrix 物化额外要求完整的具名 sensor 集合、原生 frame sensor 类型/body 或 site 对象/引用身份一致、原生行维度精确，以及 fixed variant 名称完全一致。这些 `FramePos` 读取暴露世界系位置，`FrameQuat` 保持原生 xyzw 输出。它们可与生成的跟踪 sensor 混用，并按不可变 variant context gather。

场景级 site 运动 fragment 仅接受 world-referenced 限定 site 的 `FrameLinVel` / `FrameAngVel` 声明。公共 compiler 会冻结其限定 site 目标与 sensor 身份；Motrix 在构造前 audit 原生 frame sensor 类型、site 对象、world reference、精确维度以及完整的原生 site parent/local-pose 身份，再按不可变 variant assignment 从所属 context gather 公开行。`FrameLinVel` 返回世界系 site 点速度，`FrameAngVel` 返回世界系角速度。原生验收会在世界系 root 速度转换后，用实际公开 qvel 求解公开世界系 site Jacobian，并比较两个读数。entity 内 frame 运动、引用形式与其他所有 site fragment 形式均快速失败。

场景级 body 运动 fragment 仅接受 world-referenced 限定 body 的 `FrameLinVel` / `FrameAngVel` 声明。公共 compiler 会冻结其限定 body 目标与 sensor 身份；Motrix 在构造前 audit 原生 frame sensor 类型、body 对象、world reference 和精确维度，并按不可变 variant assignment 从所属 context gather 公开行。`FrameLinVel` 返回 inertial body-frame origin 处的世界系速度（公开世界系 body-origin 线速度加世界角速度与旋转后原生 `body_ipos` 的叉积），`FrameAngVel` 返回世界系角速度。entity 内 body 运动、引用形式与其他所有 body fragment 形式均快速失败。

Entity-owned source site 运动 sensor 额外仅接受同一 entity 内具名 site 上未引用参考系的 `velocimeter` 与 `gyro` 声明。Motrix 必须把它们物化为原生 `FrameLinVel(local)` 与 `FrameAngVel(local)` sensor 且维度精确；fixed variants 也必须保持完整身份一致。其值是原生 site 坐标系运动向量：原生验收会把公开世界系 site Jacobian 结果旋转到已审计 site 坐标系并与读取值比较。accelerometer、引用参考系 sensor 与 entity 内 frame-motion 声明均快速失败。

场景级 geom-pair contact fragment 仅使用公共 `data="force" reduce="netforce"` 与 `data="found" num="1"` 形式。Motrix 在构造前 audit 每个 native contact sensor 的精确 geom pair、reduction mode 和 force/found report 标志，要求原生维度精确且 fixed variant 名称一致，并返回已完成 step 后留在原生 sensor storage 中的值。不支持的 contact reduction 与其他 site sensor 形式均快速失败。

Portable `get_site_jacobian_w()` 把限定 site 名称解析到原生 site ID，并将 Motrix 的世界系 compact Jacobian 转换为公开 `jacp`/`jacr` 张量。Fixed variants 必须拥有同一套唯一非空 site 名称，且被选中 site 的 parent 与受影响 DoF 身份一致；结果行按 assignment 从所属原生 variant context gather，请求列按冻结公开 qvel 顺序选择。非法公开 DoF 范围、site 路径未覆盖的 DoF、缺失/重复/模糊 site 身份、非法原生 shape 以及非有限值均快速失败。这只是 Jacobian 读取，不新增 site sensor 支持。

Portable `set_state()` 的选中行 reset randomization 仅覆盖 `body_mass`、`base_mass_delta`、`base_com_offset`、`body_ipos`、`dof_armature` 与 `dof_frictionloss`。公开 body 列在状态提交前预校验 exact shape、有限值和 native link 映射；随后通过所属 variant 的 `SceneData[DisjointIndices]` 切片与公开 Link mass/COM override 提交。公开 DOF 表会预校验 exact shape、有限非负值和已审计的原生标量 hinge/slide joint；选中行随后通过这些切片上的公开 Joint armature/friction-loss override 提交。无映射与 free-root 公开 DOF 列保持 variant 默认值，修改会被拒绝。原生公共 override 读回是验收证据，省略的 mass/COM/DOF 通道彼此独立，默认值保持分离，部分原生提交会使 backend 进入 faulted。Motrix 0.8.2 没有公开运行时 joint-damping override，因此 `dof_damping`、actuator gain 与其他 reset-randomization 项仍不支持。局部 `reset_entities()` 行通过 `SceneData[DisjointIndices]` 一致提交，不调用整场景 reset，并保留未提及通道、无关实体、无关环境与当前 control。`restore_default_controls=True` 时，只把被选中 entity root/joint patch 影响的 control 恢复为该 variant 冷路径捕获的原生默认值；无关 control 列与行保持不变。完整 `reset()` 会提交每个选中环境的完整 variant 默认 qpos/qvel、默认 kinematic mirror 位姿与默认 control，保留无关环境，并清除 reset 行上的全部 pending body force/torque。部分原生状态提交会使 backend 进入 faulted。其他 fixed-variant layout、optional 缺失的 uniform-public mesh slot、非 mesh 的 uniform-public 源差异、物理 kinematic 实体、其他 source sensor 形式、其他 site sensor 形式、不支持的 contact 形式、生成 terrain、其他 reset randomization、same-layout 原生播放/渲染与非一致公开 geometry 尺寸读取均快速失败。固定 link 的质量可能读为零，因为公开 mass/COM 是有效原生读回，不是源 inertial 元素的回显。
