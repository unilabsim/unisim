# ADR: Optional Backend Tensor Lifecycle

[English](adr-tensor-lifecycle.md) | [中文](../zh/adr-tensor-lifecycle.md)

## Status

Accepted (2026-09-27)

## Context

UniLab's Manager-Based runtime and collectors are NumPy-oriented, while GPU physics engines expose stable batched device arrays. Replacing every NumPy boundary with an engine-specific tensor API would break existing managers, replay, and playback consumers. CPU physics engines also need to remain useful when manager arithmetic is accelerated.

## Decision

`SimBackend` exposes an optional, fail-closed tensor lifecycle rather than a global environment replacement. `TensorExecution` distinguishes `DEVICE_RESIDENT`, `HOST_BRIDGE`, and the default `UNSUPPORTED` profile. `get_tensor_capabilities()` exposes the partial method and reset-feature limits plus the process topology, bulk data plane, stream/event ownership, and accepted Torch devices. An unsupported lifecycle must use the default in-process topology and no data plane. Valid supported combinations are in-process direct device storage, in-process host-bridge storage, external-worker CUDA IPC for device-resident physics, or external-worker host shared memory for host-bridged physics; no coarse classification implies that every optional tensor method is supported.

Since 1.7.16 this is the only public training lifecycle. The historical NumPy lifecycle was removed without aliases; see [the legacy NumPy removal ADR](adr-legacy-numpy-removal.md).

Capability construction also rejects contradictory declarations: unsupported matrices carry no feature, field, ownership, or device metadata; state views require fields; selected reset requires `qpos` and `qvel`; reset randomization requires selected reset; device reset randomization requires reset randomization on either the in-process device-resident direct-storage matrix or the in-process host-bridge matrix; and packed plans require the in-process host-bridge matrix.

Declaring adapters may implement `get_state_views()`, `get_sensor_view()`, `step_tensor()`, and `set_state_tensor()`. A host-bridge adapter may additionally advertise `packed_host_bridge` and compile a `TensorIOSpec` into a `HostBridgeTransferPlan`. Since UniLab issue #2410 the DR payload family is torch-only: `set_state_tensor()` accepts the single public `TensorResetRandomizationPayload`, whose Torch tensor fields hold final absolute selected-row values, and the payload tensors' device selects the execution plane — `torch.cpu` is the host plane, a CUDA device is the device plane. `DomainRandomizationCapabilities.supported_reset_terms` declares the host plane and `supported_device_reset_terms` the device plane; an empty set fails closed, and a term submitted on a plane that does not declare it fails closed naming the term. Device-resident adapters scatter device payloads in place, while in-process host bridges convert host-plane payloads into adapter-private NumPy host arrays inside the same explicit reset boundary. A public NumPy reset payload no longer exists; see [the torch-first DR payload ADR](adr-dr-torch-first-payloads.md).

Interval domain randomization uses the same torch-first rule. `IntervalTermOp.payload` is a Torch tensor or a `TensorIntervalPayload`, its device selects the plane, and `supported_interval_terms` / `supported_device_interval_terms` declare the host and device term sets with empty sets failing closed. Push is producer-sampled on every backend following the MJWarp device pattern: the producer owns generation and finiteness of the full-width float32 `push_force` table, and the adapter validates type, shape, dtype, device, contiguity, and finiteness before scattering it into `xfrc_applied` for consumption on the next tensor step. Backend-internal global-RNG push sampling is removed; a host adapter without a producer-sampled payload fails closed, and mixed host/device wrench staging fails closed rather than reintroducing a hidden host round-trip.

Adapters may declare the production `set_state_tensor_mask()` boundary with `mask_selected_reset`. It receives a full-width boolean mask and full-width qpos/qvel tensors, preserves every false row, resets time and persistent channels only on true rows, and publishes authoritative selected state before returning. The capability requires authoritative direct device-resident selected reset or an authoritative in-process host bridge. MJWarp publishes the mask into its reset graph; MuJoCo owns bounded true-row compaction inside its explicit tensor-to-host boundary. A declaring adapter may accept a full-width `TensorResetRandomizationPayload`, applies its final values only on true rows, and leaves every false row intact; payloads submitted on an undeclared plane fail closed. `mask_selected_reset_full_refresh` additionally requires an eager equivalent full-batch derived-state refresh.

The base package still does not depend on Torch. Adapters lazy-import their tensor runtime and own stream, layout, and transfer semantics.

An external GPU worker keeps its SDK interpreter and dependencies isolated from the host process. Its pipe carries control messages and errors only; bulk tensors cross through stable CUDA IPC arenas. The shared SDK-free transport exports opaque memory and event driver handles with ABI versions, a physical-device UUID, size, and alignment. It never serializes Torch-private storage, imports Isaac SDKs in the host process, or treats an engine-native buffer as a public stable pointer. The transport primitive does not by itself make IsaacGym or IsaacSim tensor-capable, and their existing CPU shared-memory subprocess path is not a tensor support claim.

Tensor inputs are contiguous Torch tensors. Controls are float32 `(num_envs, num_actuators)`; reset row IDs are unique int64 values in `[0, num_envs)`, and reset qpos/qvel are float32 `(rows, nq/nv)` tensors on one accepted device. Producers own finiteness so adapters do not force hot-path scalar synchronization. Row validation may perform one bounded synchronization. A completed step or reset consumes its inputs. Asynchronous device-resident stepping is ordered on the backend execution stream and exposed through an event-backed `CompletionToken` step receipt (for example an MJWarp CUDA event) rather than requiring a device-wide host synchronization; consumers gate reads through `wait_before_read()`. Receipts exist only for asynchronous step operations: reset operations and synchronous host-bridge producers emit no receipt, and receipt presence is structural, so the minimal contract negotiates no completion capability.

The event-backed step completion receipt is a backend boundary contract for asynchronous device-resident stepping only. It does not negotiate or authorize caller-owned graph capture; graph capture remains an adapter-owned physics implementation detail when a backend declares it internally.

For `DEVICE_RESIDENT`, `device=None` means the backend's exact CUDA device and returned live views are logically read-only. For `HOST_BRIDGE`, `device=None` means CPU; an explicit device requests an H2D copy and returned values are detached snapshots. `TensorLifecycleCapabilities.state_fields` is the machine-readable generalized-field set (`qpos`, `qvel`, `ctrl`, `time`, and where available `sensordata`). Body pose and velocity consumers use named sensor views rather than engine-private body-array conventions.

A packed host-bridge plan is compiled on the cold path after backend materialization. It freezes requested state and sensor shapes, offsets, dtypes, reset row-ID capacity/dtype/layout, and body IDs; preallocates host staging (pinned only for CUDA targets) and persistent Torch destinations; and exposes the four semantic boundaries separately: one packed control D2H before CPU physics, one packed full state/sensor H2D after physics, one selected-row reset D2H, and one packed selected-row post-reset H2D. Empty reset sets perform no reset transfer. Selected transfers copy a contiguous prefix before scattering rows on the accelerator. Operations carry per-boundary timing plus cumulative direction, byte, and synchronization counters. Closing the backend invalidates its plans; plans are process-local and are not serialized with an environment factory.

- MJWarp declares `DEVICE_RESIDENT` with in-process direct storage: Torch controls and selected reset rows are copied or scattered into stable MJWarp device storage, physics runs on CUDA, and DLPack exposes live state views. `step_tensor()` completes physics and leaves tracked-sensor refresh pending; the first tracked tensor sensor or `sensordata` read refreshes only device-resident state, while adapter-private generalized/body host caches refresh lazily at explicit host-format boundaries.
- MJWarp tensor stepping does not support host pre-step callbacks. Selected-row reset accepts the torch `TensorResetRandomizationPayload` on both planes: host-plane (`torch.cpu`) payloads for all 16 declared terms are converted into adapter-private NumPy host arrays at the explicit host boundary, and the device-scatterable subset (`gravity`, `body_mass`, `body_ipos`, `body_inertia`, `body_iquat`, `geom_friction`, `geom_solref`, `geom_solimp`, `dof_armature`, `dof_damping`, `dof_frictionloss`, and actuator `kp`/`kd`) is applied from device-resident payloads through in-place per-world Model row scatters without a host round-trip; scattered rows mark their host DR mirrors stale so the next host read refreshes them from the device. All entry-operand and payload value rules (finiteness, non-negativity, solref/solimp legality, unit inertial quaternions, row uniqueness) aggregate into one device-side reduction with a single D2H synchronization per reset; a failed aggregate re-checks each operand on the cold path so the error still names its field. Mass/COM/inertial-orientation scatters trigger an eager derived-constant refresh (`set_const`, or `set_const_0` for inertia/armature) before the reset-graph replay with `restore=False`, because the lazy full-width tracked-state refresh and the next `forward` recompute all derived Data state before any consumer can read it; row-scoped refresh is not available since mujoco_warp 3.11.0's `set_const` family accepts no world mask and launches every kernel with `dim=(d.nworld, ...)`. `geom_size` fails closed on the device plane because its derived `geom_rbound`/`geom_aabb` rows are computed host-side; fixed variants, pending interval wrenches, and models with mocap bodies fail closed as well. Mixed tensor writes first refresh their host mirror so unselected device rows cannot regress.
- MuJoCo/MJBatch declares an in-process `HOST_BRIDGE` and implements the packed plan: accelerator controls and reset rows cross explicit host boundaries, CPU physics remains authoritative, and requested state and sensors are packed into one stable H2D layout on the selected Torch device. Its tensor reset converts the host-plane torch reset payload into adapter-private NumPy host arrays inside its explicit tensor-to-host boundary, while packed stepping does not support host pre-step callbacks. This is a transfer-layout optimization, not a device-resident physics claim.
- SuperDex is a supported backend-owned packed `HOST_BRIDGE` tensor backend. Synthetic tracked-body sensor names share the packed state/sensor H2D boundary, while authored accelerometers are declared-but-unused and fail closed when requested or bound. It accepts CPU/CUDA tensors; fixed variants, reset randomization, and host pre-step callbacks fail closed. Promotion is based on the #1678 packed-boundary counter audit, same-engine publication/control parity, full-public G1 parity, hidden-transfer profile, host-path checks, and the 2048-environment runtime benchmark; it is not a claim of MuJoCo contact/solver equivalence.
- MotrixSim is a supported backend-owned packed `HOST_BRIDGE` tensor backend for initial no-variant whole-MJCF and portable profiles. It keeps CPU physics authoritative, accepts CPU/CUDA tensors, freezes public mappings and selected-row scratch on the cold path, and preserves the one-transfer-per-boundary contract. Selected reset randomization and the packed reset transaction support the runtime-negotiated Motrix field subset; fixed variants and host pre-step callbacks fail closed. Promotion is based on #1680 whole/portable lifecycle parity, hidden-host-copy audits, quaternion/public-layout tests, and the idle 2048-environment G1 benchmark.
- Drake is a supported backend-owned packed `HOST_BRIDGE` tensor backend with the same one-transfer-per-boundary contract. It accepts CPU/CUDA tensors, keeps CPU physics authoritative, converts between float32 packets and authoritative float64 Drake state explicitly, publishes public tracked-body views through the packed state/sensor boundary, and fails closed for fixed variants, reset randomization, host pre-step callbacks, backend-specific unsupported reset work, and pending interval body forces. Promotion is based on #1679 precision parity, selected-row isolation, packed counter tests, native-runtime construction validation, and the 2048-environment G1 benchmark.
- Newton is a supported narrow in-process direct `DEVICE_RESIDENT` tensor backend for one CUDA-bound articulation and for portable multi-entity scenes. It covers `qpos`/`qvel`, callback-free tensor stepping, selected reset, and the negotiated scalar/tracked-body sensor subset derived from public Newton link arrays; the negotiated scalar set includes `pelvis_local_linvel`, `torso_gyro`, and the `torso_upvector` frame-z-axis. Single-entity portable scenes reuse the whole-model paths; multi-entity portable scenes gather and scatter full-scene public-layout state through the per-entity articulation views, with #432 acceptance stepping selected rows against per-entity single-model reference backends. CUDA graph/eager parity, hidden-transfer audit, canonical G1 gross-threshold acceptance, and the 2048-environment G1 benchmark close the single-articulation promotion evidence. Other sensors, portable reset randomization and packed reset, fixed variants, and host pre-step callbacks fail closed.
- Newton also exposes per-substep generalized-force injection on the same profiles, portable multi-entity scenes included. `set_generalized_force_tensor()` uploads `joint_f` (a `(num_envs, nv)` tensor in public qvel column order) into Newton's `Control.joint_f` — routed per entity through the portable articulation views on multi-entity scenes — and `body_f` (a `(num_envs, num_bodies, 6)` tensor of world-frame center-of-mass spatial wrenches in public body order) into an adapter-owned persistent device buffer, permuted from public body order into the native flat body layout on portable scenes. The adapter calls `state.clear_forces()` at the start of every substep, which resets `state.body_f` and never touches `Control.joint_f`; the persistent wrench buffer is therefore re-applied after every clear, so one write is consumed by every substep of `step_tensor(nsteps=k)` under eager and CUDA-graph execution until overwritten. Both channels are control inputs that tensor/host resets do not clear, a `None` channel is left unchanged, and an all-zeros write disarms a channel. The contract is the engine's own semantics (a virtual-object-controller wrench and an actuator-less joint PD servo), not a new force model.
- Genesis is a narrowly gated supported in-process direct `DEVICE_RESIDENT` tensor backend for one non-portable CUDA-bound articulation using Genesis' exact CUDA backend, zero-copy session, and public Torch getters. It covers `qpos`/`qvel`, callback-free tensor stepping, reviewed non-portable selected reset, and a negotiated scalar/tracked-body sensor subset (`pelvis_local_linvel`, `torso_gyro`, and the `torso_upvector` frame-z-axis). Stable backend-owned CUDA mirrors absorb Genesis 1.3.3's copying/non-contiguous public getter results without a bulk host detour. CPU/ROCm, portable multi-entity, zero-copy-disabled, unsupported sensor, randomization, fixed-variant, and callback paths fail closed. Promotion is based on canonical G1 gross-threshold parity, hidden-transfer attribution, a 2048-environment benchmark, and independent physical-GPU acceptance; the tracked-body velocity spread is contact/solver divergence (also visible in the MJWarp control pair), not a publication-frame claim, and this is not portable Genesis support.
- IsaacGym is a narrowly gated supported external-worker CUDA IPC tensor backend for the reviewed mapped-scene GPU-pipeline profile. Preview 4 stays in its Python 3.8 worker and the host never imports IsaacGym; metadata-only worker commands, same-GPU raw arenas/events, and D2D native projections cover `qpos`/`qvel`, callback-free stepping, selected reset, and the negotiated G1 scalar/tracked-body views. Selected reset declares `AUTHORITATIVE_VIEWS`: native root/DOF writes are committed and the worker refreshes and projects the derived body/scalar arenas on its stream before replying, so public state/sensor views are readable immediately and `step_tensor()` is never a readiness barrier. `pelvis_local_linvel` includes the sensor-site point velocity. Reset randomization, fixed variants, callbacks, contact/body-wrench views, unsupported sensors, CPU/model-file tensor pipelines, and cross-device IPC fail closed. Promotion is based on full-G1 and repeated mapped-generalized acceptance, hidden-transfer profiling, fault/shutdown lifecycle coverage, same-GPU dual-worker evidence, and the 2048-environment benchmark; it is not multi-GPU scaling or arbitrary importer support.
- IsaacSim is a narrowly gated supported external-worker CUDA IPC tensor backend for opt-in mapped entity scenes. Kit/IsaacLab stays in the dedicated worker; same-GPU raw arenas/events replace the model-file CPU shared-memory bridge for device-resident `qpos`/`qvel`, callback-free stepping, mapped selected reset, and negotiated scalar/tracked-body sensor views. Worker commands carry metadata only; reset randomization, fixed variants, host callbacks, unsupported sensors, model-file scenes, and CUDA absence fail closed. The public Manager surface additionally includes canonical `get_public_state_widths()`, inventory-backed entity-qualified sensor/body names, and aggregate `get_tracked_body_views()` blocks; the latter use owner-qualified logical body names so duplicate local body names fail closed. Selected reset declares `AUTHORITATIVE_VIEWS`: qpos/qvel, scalar sensors, and tracked-body blocks are public immediately when `set_state_tensor()` returns, with no readiness physics step. Native/reset/publication faults mark the worker faulted and subsequent CUDA IPC commands fail closed. #350 evidence adds mapped multi-entity acceptance, full-G1 acceptance, mapped physics-state playback acceptance, and 8/2048-environment phase-local regression artifacts under `scripts/benchmark/outputs/isaacsim-issue350/`. Promotion is based on full-G1 large-finite-box acceptance, mapped multi-entity generalized acceptance, hidden-transfer audit, fault/shutdown lifecycle coverage, a 2048-environment benchmark, and concurrent two-worker/same-GPU evidence. It is not contact-sensor support, infinite-plane support, or a production multi-GPU scaling claim.
- Issue #2387 extends both reviewed Isaac CUDA IPC lanes to the packed reset transaction. Device arenas carry selected-row actuator `kp`/`kd` tables, and each worker exposes one explicitly named reset-only property bridge for its CPU-native PhysX/actor setters. Step, state, control, and sensor hot paths remain free of host detours; fixed variants, callbacks, unsupported fields, model-file tensor lanes, and cross-device IPC continue to fail closed.
- Every unreviewed adapter or runtime profile remains tensor `UNSUPPORTED` in the public support matrix and raises `NotImplementedError` rather than silently converting through NumPy. In particular, IsaacGym's existing CPU shared-memory subprocess path is not a tensor support claim.

## Consequences

The contract is torch-first and carries no NumPy lifecycle: NumPy survives only on serialization and cold-path leaves, and host-device boundaries are measurable. Its completion surface is deliberately minimal — only event-backed asynchronous step receipts exist, with no reset receipts, no synchronous host-bridge receipts, and no cross-process receipt export — so it is not a complete GPU collector/replay protocol: `uni_rl`, IPC, replay ingress, and Manager-Based task dispatch require separate versioned migration. Backend callers must validate producer tensors where hot-path value checks would otherwise force scalar device synchronization, while adapters continue to validate metadata and fail closed for unsupported lifecycle features.
