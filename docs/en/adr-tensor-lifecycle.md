# ADR: Optional Backend Tensor Lifecycle

[English](adr-tensor-lifecycle.md) | [中文](../zh/adr-tensor-lifecycle.md)

## Status

Accepted (2026-09-27)

## Context

UniLab's Manager-Based runtime and collectors are NumPy-oriented, while GPU physics engines expose stable batched device arrays. Replacing every NumPy boundary with an engine-specific tensor API would break existing managers, replay, and playback consumers. CPU physics engines also need to remain useful when manager arithmetic is accelerated.

## Decision

`SimBackend` exposes an optional, fail-closed tensor lifecycle rather than a global environment replacement. `TensorExecution` distinguishes `DEVICE_RESIDENT`, `HOST_BRIDGE`, and the default `UNSUPPORTED` profile. `get_tensor_capabilities()` exposes the partial method and reset-feature limits plus the process topology, bulk data plane, stream/event ownership, and accepted Torch devices. An unsupported lifecycle must use the default in-process topology and no data plane. Valid supported combinations are in-process direct device storage, in-process host-bridge storage, external-worker CUDA IPC for device-resident physics, or external-worker host shared memory for host-bridged physics; no coarse classification implies that every optional tensor method is supported.

Capability construction also rejects contradictory declarations: unsupported matrices carry no feature, field, ownership, or device metadata; state views require fields; selected reset requires `qpos` and `qvel`; reset randomization requires selected reset; device reset randomization requires reset randomization on the in-process device-resident direct-storage matrix; and packed plans require the in-process host-bridge matrix.

Declaring adapters may implement `get_state_views()`, `get_sensor_view()`, `step_tensor()`, and `set_state_tensor()`. A host-bridge adapter may additionally advertise `packed_host_bridge` and compile a `TensorIOSpec` into a `HostBridgeTransferPlan`. `set_state_tensor()` accepts the host NumPy `ResetRandomizationPayload` and, only when the adapter declares `device_reset_randomization`, a `TensorResetRandomizationPayload` whose engine-native device arrays hold final absolute selected-row values for in-place scatter; every other adapter fails closed on the device payload.

The base package still does not depend on Torch. Adapters lazy-import their tensor runtime and own stream, layout, and transfer semantics.

An external GPU worker keeps its SDK interpreter and dependencies isolated from the host process. Its pipe carries control messages and errors only; bulk tensors cross through stable CUDA IPC arenas. The shared SDK-free transport exports opaque memory and event driver handles with ABI versions, a physical-device UUID, size, and alignment. It never serializes Torch-private storage, imports Isaac SDKs in the host process, or treats an engine-native buffer as a public stable pointer. The transport primitive does not by itself make IsaacGym or IsaacSim tensor-capable, and their existing CPU shared-memory subprocess path is not a tensor support claim.

Tensor inputs are contiguous Torch tensors. Controls are float32 `(num_envs, num_actuators)`; reset row IDs are unique int64 values in `[0, num_envs)`, and reset qpos/qvel are float32 `(rows, nq/nv)` tensors on one accepted device. Producers own finiteness so adapters do not force hot-path scalar synchronization. Row validation may perform one bounded synchronization. A completed step or reset consumes its inputs and synchronizes backend work.

For `DEVICE_RESIDENT`, `device=None` means the backend's exact CUDA device and returned live views are logically read-only. For `HOST_BRIDGE`, `device=None` means CPU; an explicit device requests an H2D copy and returned values are detached snapshots. `TensorLifecycleCapabilities.state_fields` is the machine-readable generalized-field set (`qpos`, `qvel`, `ctrl`, `time`, and where available `sensordata`). Body pose and velocity consumers use named sensor views rather than engine-private body-array conventions.

A packed host-bridge plan is compiled on the cold path after backend materialization. It freezes requested state and sensor shapes, offsets, dtypes, reset row-ID capacity/dtype/layout, and body IDs; preallocates host staging (pinned only for CUDA targets) and persistent Torch destinations; and exposes the four semantic boundaries separately: one packed control D2H before CPU physics, one packed full state/sensor H2D after physics, one selected-row reset D2H, and one packed selected-row post-reset H2D. Empty reset sets perform no reset transfer. Selected transfers copy a contiguous prefix before scattering rows on the accelerator. Operations carry per-boundary timing plus cumulative direction, byte, and synchronization counters. Closing the backend invalidates its plans; plans are process-local and are not serialized with an environment factory.

- MJWarp declares `DEVICE_RESIDENT` with in-process direct storage: Torch controls and selected reset rows are copied or scattered into stable MJWarp device storage, physics runs on CUDA, and DLPack exposes live state views. `step_tensor()` completes physics and leaves tracked-sensor refresh pending; the first tracked tensor sensor or `sensordata` read refreshes only device-resident state, and legacy NumPy generalized/body host caches lazily refresh only when mixed back in.
- MJWarp tensor stepping does not support host pre-step callbacks. Selected-row reset applies host NumPy randomization payloads and, for the device-scatterable subset (`body_mass`, `body_ipos`, `geom_friction`, and actuator `kp`/`kd`), device-resident `TensorResetRandomizationPayload` values through in-place per-world Model row scatters without a host round-trip; scattered rows mark their host DR mirrors stale so the next host read refreshes them from the device, and mass/COM scatters trigger an eager derived-constant refresh before the reset-graph replay. Other device-payload fields, fixed variants, pending interval wrenches, and models with mocap bodies fail closed. Mixed legacy writes first refresh their host mirror so unselected device rows cannot regress.
- MuJoCo/MJBatch declares an in-process `HOST_BRIDGE` and implements the packed plan: accelerator controls and reset rows cross explicit host boundaries, CPU physics remains authoritative, and requested state and sensors are packed into one stable H2D layout on the selected Torch device. Its tensor reset delegates the existing NumPy reset-randomization payload to the host adapter, while packed stepping does not support host pre-step callbacks. This is a transfer-layout optimization, not a device-resident physics claim.
- SuperDex is a supported backend-owned packed `HOST_BRIDGE` tensor backend. Synthetic tracked-body sensor names share the packed state/sensor H2D boundary, while authored accelerometers are declared-but-unused and fail closed when requested or bound. It accepts CPU/CUDA tensors; fixed variants, reset randomization, and host pre-step callbacks fail closed. Promotion is based on the #1678 packed-boundary counter audit, same-engine publication/control parity, full-public G1 parity, hidden-transfer profile, legacy-path checks, and the 2048-environment runtime benchmark; it is not a claim of MuJoCo contact/solver equivalence.
- MotrixSim is a supported backend-owned packed `HOST_BRIDGE` tensor backend for initial no-variant whole-MJCF and portable profiles. It keeps CPU physics authoritative, accepts CPU/CUDA tensors, freezes public mappings and selected-row scratch on the cold path, and preserves the one-transfer-per-boundary contract. Reset randomization, fixed variants, and host pre-step callbacks fail closed. Promotion is based on #1680 whole/portable lifecycle parity, hidden-host-copy audits, quaternion/public-layout tests, and the idle 2048-environment G1 benchmark.
- Drake is a supported backend-owned packed `HOST_BRIDGE` tensor backend with the same one-transfer-per-boundary contract. It accepts CPU/CUDA tensors, keeps CPU physics authoritative, converts between float32 packets and authoritative float64 Drake state explicitly, publishes public tracked-body views through the packed state/sensor boundary, and fails closed for fixed variants, reset randomization, host pre-step callbacks, backend-specific unsupported reset work, and pending interval body forces. Promotion is based on #1679 precision parity, selected-row isolation, packed counter tests, native-runtime construction validation, and the 2048-environment G1 benchmark.
- Newton is a supported narrow in-process direct `DEVICE_RESIDENT` tensor backend for one CUDA-bound articulation. It covers `qpos`/`qvel`, callback-free tensor stepping, the reviewed non-portable selected-reset profile, and the negotiated scalar/tracked-body sensor subset derived from public Newton link arrays; the negotiated scalar set includes `pelvis_local_linvel`, `torso_gyro`, and the `torso_upvector` frame-z-axis. CUDA graph/eager parity, hidden-transfer audit, canonical G1 gross-threshold acceptance, and the 2048-environment G1 benchmark close the promotion evidence. Other sensors, portable multi-entity selected reset, reset randomization, fixed variants, and host pre-step callbacks fail closed.
- Genesis is a narrowly gated supported in-process direct `DEVICE_RESIDENT` tensor backend for one non-portable CUDA-bound articulation using Genesis' exact CUDA backend, zero-copy session, and public Torch getters. It covers `qpos`/`qvel`, callback-free tensor stepping, reviewed non-portable selected reset, and a negotiated scalar/tracked-body sensor subset (`pelvis_local_linvel`, `torso_gyro`, and the `torso_upvector` frame-z-axis). Stable backend-owned CUDA mirrors absorb Genesis 1.3.3's copying/non-contiguous public getter results without a bulk host detour. CPU/ROCm, portable multi-entity, zero-copy-disabled, unsupported sensor, randomization, fixed-variant, and callback paths fail closed. Promotion is based on canonical G1 gross-threshold parity, hidden-transfer attribution, a 2048-environment benchmark, and independent physical-GPU acceptance; the tracked-body velocity spread is contact/solver divergence (also visible in the MJWarp control pair), not a publication-frame claim, and this is not portable Genesis support.
- IsaacGym is a narrowly gated supported external-worker CUDA IPC tensor backend for the reviewed mapped-scene GPU-pipeline profile. Preview 4 stays in its Python 3.8 worker and the host never imports IsaacGym; metadata-only worker commands, same-GPU raw arenas/events, and D2D native projections cover `qpos`/`qvel`, callback-free stepping, selected reset, and the negotiated G1 scalar/tracked-body views. Selected reset declares `AUTHORITATIVE_VIEWS`: native root/DOF writes are committed and the worker refreshes and projects the derived body/scalar arenas on its stream before replying, so public state/sensor views are readable immediately and `step_tensor()` is never a readiness barrier. `pelvis_local_linvel` includes the sensor-site point velocity. Reset randomization, fixed variants, callbacks, contact/body-wrench views, unsupported sensors, CPU/legacy tensor pipelines, and cross-device IPC fail closed. Promotion is based on full-G1 and repeated mapped-generalized acceptance, hidden-transfer profiling, fault/shutdown lifecycle coverage, same-GPU dual-worker evidence, and the 2048-environment benchmark; it is not multi-GPU scaling or arbitrary importer support.
- IsaacSim is a narrowly gated supported external-worker CUDA IPC tensor backend for opt-in mapped entity scenes. Kit/IsaacLab stays in the dedicated worker; same-GPU raw arenas/events replace the legacy CPU shared-memory bridge for device-resident `qpos`/`qvel`, callback-free stepping, mapped selected reset, and negotiated scalar/tracked-body sensor views. Worker commands carry metadata only; reset randomization, fixed variants, host callbacks, unsupported sensors, legacy scenes, and CUDA absence fail closed. The public Manager surface additionally includes canonical `get_public_state_widths()`, inventory-backed entity-qualified sensor/body names, and aggregate `get_tracked_body_views()` blocks; the latter use owner-qualified logical body names so duplicate local body names fail closed. Selected reset declares `AUTHORITATIVE_VIEWS`: qpos/qvel, scalar sensors, and tracked-body blocks are public immediately when `set_state_tensor()` returns, with no readiness physics step. Native/reset/publication faults mark the worker faulted and subsequent CUDA IPC commands fail closed. #350 evidence adds mapped multi-entity acceptance, full-G1 acceptance, mapped physics-state playback acceptance, and 8/2048-environment phase-local regression artifacts under `scripts/benchmark/outputs/isaacsim-issue350/`. Promotion is based on full-G1 large-finite-box acceptance, mapped multi-entity generalized acceptance, hidden-transfer audit, fault/shutdown lifecycle coverage, a 2048-environment benchmark, and concurrent two-worker/same-GPU evidence. It is not contact-sensor support, infinite-plane support, or a production multi-GPU scaling claim.
- Every unreviewed adapter or runtime profile remains tensor `UNSUPPORTED` in the public support matrix and raises `NotImplementedError` rather than silently converting through NumPy. In particular, IsaacGym's existing CPU shared-memory subprocess path is not a tensor support claim.

## Consequences

The contract keeps the existing NumPy lifecycle compatible and makes host-device boundaries measurable. It is not yet a complete GPU collector/replay protocol: `uni_rl`, IPC, replay ingress, and Manager-Based task dispatch require separate versioned migration. Backend callers must validate producer tensors where hot-path value checks would otherwise force scalar device synchronization, while adapters continue to validate metadata and fail closed for unsupported lifecycle features.
