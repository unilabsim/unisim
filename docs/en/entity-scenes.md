# Entity scene execution

[English](entity-scenes.md) | [中文](../zh/entity-scenes.md)

This page describes how adapters execute the public entity, immutable identity and selected-reset contracts defined by the [entity decision](adr-entities.md). The cold authoring/compilation boundary is defined by the [portable MJCF decision](adr-portable-mjcf.md). MuJoCo-family adapters compile and execute complete scenes; Isaac adapters retain their dedicated workers and native execution.

Legacy compiled MuJoCo/MJWarp scenes use the same cold `CompiledModelIndex` audit internally. It records native body partitions, roots, joint qpos/qvel addresses, mocap addresses and actuator transmission/control columns without renaming anonymous objects or pretending tendon/site/root transmissions are scalar joint actuators. Old whole-model APIs retain their source semantics; the restricted entity layout is only exposed when its partition cross-check passes.

## Source preparation and identity

The common portable MJCF compiler validates sources, defaults, names, referenced resources and same-layout variants; produces expanded MJCF, frozen `CompiledSceneLayout`, source/intent report and content identity. Standalone worker assets receive explicit compiler-derived body inertials and joint limits. Geometry names, body ownership, source contact masks, source friction and sphere radii also travel in the cold-path intent table, preserving each body's source geom order. Actuators are removed from exported XML after their unit-gear position-drive intent has been validated and copied into a separate table; the native MJCF importers cannot safely consume MuJoCo's canonical general-actuator spelling. Source passive joint damping/springs, activation state, unsupported transmissions and non-scalar joints fail closed in this profile. Compiled per-environment actuator control limits apply to step targets and initial/full-reset controls; unlimited controls are not clamped to a stored zero range.

Cross-entity pair declarations live in a scene-level sensor-only `fragment_files` entry. Portable identity includes fragment bytes. MuJoCo consumes both `contact data="force" reduce="netforce"` sensors and `contact data="found" num="1"` sensors from the final expanded MJCF; mapped IsaacSim consumes the force/netforce form through `ContactSensor` filters.

Generated filenames use safe internal USD identifiers; they do not define public entity identity. Post-compilation edits are serialized from the current spec, avoiding stale last-compiled XML. The host retains the generated full scenes and standalone sources until worker shutdown. Worker-returned entity names, complete assignment and actual instance masses are checked against compiled intent. Worker audits additionally establish native topology, drive, inertia and selected visual sphere-radius adoption. Echo alone is not an independent asset identity proof.

Newton consumes the portable compiler's complete per-variant MJCF files rather than homogeneous template replication. It imports each source into an independent public `ModelBuilder`, assigns the selected source to each `begin_world()` world, and binds one public `ArticulationView` per physical entity. Cold-path audits compare the effective per-world gravity, masses, COMs, inertia tensors, shape types and shape dimensions against each selected source before solver construction. The bounded profile covers multiple articulations and multiple free roots per world, fixed roots, passive entities, static rigid entities, same-layout same-shape-type heterogeneous variants and force response, selected entity reset/playback, and named geom-pair found sensors with per-world attribution. Kinematic mirrors and mixed shape-type assignments fail closed.

Portable Newton selected resets preserve unrelated state and controls, clear the selected entity's controls, and fail closed for `restore_default_controls`. Keyframe/default control restoration is not claimed.

The host publishes separate nq/nv/nu and entity root layouts. Public root state uses link-origin position/linear velocity, wxyz quaternion and world angular velocity with clone offsets removed exactly once by the adapter. Full generalized qvel retains body-frame angular velocity. Passive joints contribute state but no implicit action columns.

## Reset and control

All entity patches are validated before materializing or writing native state. Prepared rows and explicit masks pass through one versioned reset command. Existing full qpos/qvel writes on the new entity entry point normalize into the same patch submission. Full `reset()` restores each selected environment's variant defaults and independent keyframe control; controls need not equal joint positions. Other environments and unselected entities retain their state and targets.

IsaacGym accumulates indexed root/DoF submissions until the next physics step, because a second indexed setter can otherwise overwrite an earlier reset. Native COM velocity is converted at both directions of the public link-origin boundary. Root and joint state is available immediately; articulation descendant body/sensor state after initialization or affected resets is explicitly unavailable until the next step. The host refuses those reads instead of presenting stale values as current. The legacy model-file path behaves differently: PhysX cannot refresh link poses without stepping, so between an INIT keyframe or `set_state` and the first physics step the worker overlays exact MJCF forward kinematics onto freshly written environments — positions, orientations and link-origin/angular velocities computed from the effective generalized state — and clears their stale contact-force rows. The host scans the kinematic tree into the INIT payload (per variant under fixed variants) and fails closed when it disagrees with the adopted public body/joint layout. Legacy reset input follows the canonical generalized-velocity contract (world link-origin linear velocity, body-frame angular velocity); the historical COM-velocity projection is retained only on the published legacy output buffers.

Unrecoverable native commit failures set the worker fault marker and the host refuses further state or step use. Validation failures before native submission preserve the session. Shared-memory slot shapes/dtypes are checked before attachment, including zero-width action or state layouts.

## Inspection and playback

Versioned worker configuration reports are required and checked before being accepted. Entity assignment, body masses and geometry have scoped records distinguishing source intent from instance readback; source values never stand in for missing runtime fields. For a mapped IsaacSim scene, INIT validates the native mass, COM and geometry records, then `get_body_mass()` returns a detached `(num_envs, nbody)` table by scattering those worker-native snapshots into frozen public body order. Unowned public rows retain their canonical compiled-source values; body mass is readback-only because reset-time mutation is unsupported. `get_body_ipos()` returns the detached canonical compiled-source default of shape `(nbody, 3)`, while `get_body_ipos(env_ids=...)` returns detached worker-native materialization rows of shape `(len(env_ids), nbody, 3)`, preserving empty, duplicate and reordered selections. Public geometry is ordered by frozen entity/geom records: `get_geom_names()` returns qualified names, `get_geom_body_ids()` returns their public owning body IDs, `get_geom_contact_masks()` reports normalized native collider enablement as matching contype/conaffinity rows, and `get_geom_friction()` returns detached worker-native PhysX material rows of shape `(num_envs, ngeom, 3)` as `[static, dynamic, 0]`. Initial materials follow immutable variant assignment; selected resets may replace current material rows, and an ordinary state reset does not silently restore them. Collision state remains role-immutable. The worker reads identity and materials from actual spawned collision prims and rejects count, name, ownership, mask or material drift. The separate visual `Sphere.radius` audit remains a bounded sphere-profile check, not a dimension API.

Mapped `set_state()` accepts the existing `ResetRandomizationPayload` for selected-environment `geom_friction` writes. Friction is an absolute dense public-layout table and must be finite nonnegative with `static == dynamic` and an exact zero third column. The command reuses `RESET_ENTITIES`, writes through the mapped public PhysX material views, reads native values back after the write, verifies selected and untouched rows, refreshes host current-value getters, and faults the worker on a native write/readback failure. `body_mass` fails closed at the capability boundary: on the current IsaacSim GPU-pipeline profile, a public mass write can update readback while the active solver retains stale mass until a later nonzero solver step, and reset cannot silently advance physics. Gravity remains unsupported because it is simulation-global rather than selected-environment state. Body mass, inertia and COM remain unsupported for reset mutation; source-level `set_coms()` presence is not COM evidence. Joint damping/frictionloss remain unsupported because source passive damping and imported drive damping do not have one defensible public current boundary, and actuator `kp`/`kd` remain unsupported because the available getters are immutable INIT/source values rather than post-reset current values. Geometry dimensions, other contact parameters, and all other reset terms also fail closed. The versioned import report describes materialization and must not be treated as post-reset current-value readback. Complete selected-environment scene sources are returned for playback, retaining robot, object, table and mirror. Native rendering remains worker-owned; mapped-worker physics snapshot export is not yet exposed by this slice.

The current native camera profile captures the first entity in environment 0 with its existing tracking behavior. Only `cam_distance`, `cam_elevation` and `cam_azimuth` configure capture. Nondefault `cam_lookat`, `cam_tracking`, `cam_tracking_env_idx`, `cam_tracking_extra_envs` or `cam_fov` raise `NotImplementedError` before worker access, including repeated renderer initialization. Default `CameraCfg` values retain the existing native view; they do not select the MuJoCo grid camera. Interactive viewers also reject custom spherical offsets, because their view is controlled by the native viewer. Returning the complete source for any selected environment does not imply that native cameras can select that environment.

IsaacSim maps immutable same-drive assignments by converting K unique prototypes and copying the selected prototype to each exact environment path. Assignment is fixed at construction and is never resampled. One-body rigid views, fixed-root mode, environment view-row mapping, mass/COM/inertia and selected visual sphere radii are audited; topology, drive, and source-format limits still fail closed. The common host only enables the documented MJCF scalar-joint profiles, not URDF or all PhysX asset features.

IsaacSim caches two immutable cold-path USD stages. The raw cache stores expanded-MJCF-to-raw-USD converter output under `~/.cache/unisim/isaacsim/raw-usd`; set `UNISIM_ISAACSIM_RAW_USD_CACHE` to an absolute path, or use the read-only legacy fallback `UNILAB_ISAACSIM_RAW_USD_CACHE`. Raw identity extends the portable scene content identity with the expanded source digest, importer parameters, IsaacSim/IsaacLab/MJCF-importer/Python versions, entity, and variant. The role cache stores independently baked USD under `~/.cache/unisim/isaacsim/role-usd`; set `UNISIM_ISAACSIM_ROLE_USD_CACHE` to an absolute path, or use the read-only legacy fallback `UNILAB_ISAACSIM_ROLE_USD_CACHE`. An empty value or `0`, `false`, `no`, `off`, `none`, or `disabled` (case-insensitive) disables either cache independently. Role identity extends the raw identity and immutable raw-artifact fingerprint with the source/role entity, variant, kind, root mode, collision/mirror settings, and bake parameters. Hits validate the complete manifest, file inventory, sizes, and SHA-256 digests; conversion and bake output is staged and atomically published, while malformed, interrupted, or corrupted entries are treated as misses and replaced. A role miss copies the complete raw artifact before baking. A role hit re-reads variant metadata, native body paths, articulation/rigid topology, mobility, gravity, collision, and disabled converter drives before native materialization, prim/view construction, parameter readback, capability checks, and effective-report validation. Disabling the role cache still produces an independent temporary copy per role, so role edits never mutate cached raw USD or another role.

Mapped IsaacSim scenes serve `<contact data="force" reduce="netforce"/>` through IsaacLab `ContactSensor` filters. The value is the filtered normal contact force in newtons, expressed as a world-frame 3-vector on the `geom1` source body due to the `geom2` target body; IsaacLab sums the contact points. `get_sensor_data()` returns the final completed physics substep, does not average substeps, returns zero when that pair has no contact, and reset clears stale rows. Body-net `data="found"` and unsupported reductions fail closed. The legacy reserved body-net slot is never exposed as a pair query. SDK-free checks pin the declaration, wire, row mapping and reset semantics; the gated real-worker suite checks static 1 kg and 2 kg support forces.

Mapped IsaacSim also supports world-frame `body_force` and `body_torque` interval wrenches at the native body COM. Submissions accumulate until the next step, apply for every requested substep, and are consumed afterward. Entity resets clear the selected entity bodies and full resets clear every staged body row. A mapped scene also accepts the existing host-owned `set_pre_step_control()` callback: the host issues one worker STEP per public substep and refreshes shared state before each callback. Callback control and dynamic wrenches are recomposed from scratch, compose additively with the staged interval wrench, and are consumed when the step call finishes. This is a correctness host loop, not the device-resident controller or performance path tracked by #152; legacy model-file callbacks remain unsupported.

## Drake bounded portable profile

Drake consumes the common portable compiler's expanded MJCF and accepts its layout only after public DrakeUni model information and body lookups agree with the frozen `CompiledSceneLayout`: dimensions, global body names and IDs, every root and scalar-joint qpos/qvel mapping, complete joint consumption, actuator names/order, and actuator target addresses all bind exactly. Fixed roots are read through public body-state queries; floating roots use generalized-state snapshots. Passive joints contribute state and velocity but no implicit control columns.

Selected entity resets snapshot the complete scene state, apply already validated patches, and submit complete coherent rows through public DrakeUni reset. Unselected entities and environments preserve their state. A native reset failure faults the backend. `restore_default_controls=True` is rejected before mutation because DrakeUni reset does not preserve an explicit control-restore contract. Entity mode also rejects implicit single-root base/body-frame helpers.

This first Drake profile supports only no-variant MJCF physical entities with fixed or floating roots, passive scalar joints, and fixed rigid static bodies. Fixed variants and kinematic mirrors fail closed before DrakeUni is loaded or a portable model is materialized. Native Drake acceptance is mandatory for a support claim; optional tests skip when the Drake native batch extension is unavailable. The multi-entity layout ordering fix in DrakeUni must be present (the current released `drake-uni==0.1.0` predates it).

## Genesis bounded portable profile

Genesis uses the common portable compiler as its layout, identity, provenance and source-relationship authority. The adapter normalizes each source through the common loader, serializes independent Genesis-owned MJCF inputs, and adds each public entity separately to one native `Scene`. Materialization accepts the entity only when its native state dimensions, actual link names, native inertia matrices, joint addresses, actuator order and PD gains match the independently compiled source; binding never assumes Genesis link order. Public qpos/qvel, body and actuator columns are then scattered to their owning entities, while passive entities contribute state but no control columns.

The first profile covers fixed-root articulations, floating passive articulations, floating heterogeneous rigid objects and fixed static rigid bodies. Heterogeneous variants are restricted to one-link rigid entities. Because Genesis 1.3.3 assigns an iterable of MJCF morphs itself, construction accepts only the exact public balanced mapping expected from that native behavior—K variants over N environments dispatch as contiguous blocks, with the first remainder-sized block receiving one extra environment. For N5/K2 this is `[0,0,0,1,1]`; `[1,1,0,1,0]` is rejected before Genesis scene construction. This owner-side mapping check is independent of Genesis' private solver helpers.

Selected `set_state()` and `reset_entities()` submit only selected rows to the owning native entities, preserving unrelated entities and environments. A partial native state-submission failure faults the backend. Portable mode declares no reset randomization and rejects mirrors, kinematic entities, cross-entity sensor fragments, source sensor mapping, reset-time body-force mapping, `restore_default_controls=True`, geometry contact-mask aggregation across independent entities, and the legacy single-primary-DoF view. Fixed-root world placement is passed through the public MJCF morph position/quaternion arguments because native Genesis ignores the normalized fixed-root body position during this import path.

Portable geometry exposes only frozen qualified names, public IDs and owning body IDs. Construction audits every source variant's named native visual instance by name, owning link, exact active environment rows and reviewed source AABB bounds; current support is limited to spheres and boxes, while unsupported geometry types and ambiguous or missing native identity fail closed. Geometry sizes, friction, contact masks and other geometry properties remain unsupported. The primary source's native link inertia matrices are checked against the compiled diagonal inertia and orientation, but arbitrary inertia readback is not exposed. Heterogeneous inertia records plus free-body response provide bounded native evidence; because the acceptance variants also differ in mass, COM and radius, that response does not isolate inertia alone.

Native variant mass is read through the public Genesis mass getter and scattered into frozen public body rows; selected-environment `get_body_ipos(env_ids=...)` exposes variant COM rows, while no-argument `get_body_ipos()` remains the canonical `(nbody, 3)` default table. These are readback claims, not reset-mutation claims.

## Motrix bounded portable profile

Motrix imports the common compiler's complete expanded multi-root MJCF through the public `msd.from_file()` and `msd.build()` APIs. Construction accepts entity mode only after actual Motrix metadata agrees with the frozen `CompiledSceneLayout`: qpos/qvel/actuator dimensions, native link names, floating-root and scalar-joint state addresses, complete generalized-state ordering, actuator names/order/targets, and geom names/order. Public body and geom IDs scatter through those audited native maps rather than assuming Motrix link or geom order.

The first profile covers no-variant fixed/floating physical entities, passive scalar joints and fixed rigid static bodies. Selected `reset_entities()` rows are submitted coherently through `SceneData[DisjointIndices]` without a whole-scene reset, preserving omitted channels, unrelated entities, unrelated environments and current controls. A partial native state submission faults the backend. `restore_default_controls=True`, fixed variants, kinematic mirrors, cross-entity sensor fragments, source sensors, tracking sensors, generated terrain and reset randomization fail closed. Portable selected-environment COM readback uses Motrix' native link rows; fixed-link mass may read as zero because this is effective native readback, not an echo of the source inertial element.

## Adapter profiles

| Adapter | Current profile | Binding and reset boundary |
| --- | --- | --- |
| MuJoCo | MJCF sources with fixed/floating/kinematic entities, mirrors, passive joints and same-layout variants. | One compiled `mjbatch` scene uses frozen public addresses; selected resets scatter only affected rows and preserve unrelated channels. |
| Motrix | No-variant MJCF fixed/floating physical entities, passive scalar joints and fixed rigid static bodies. | One common expanded portable model is imported through Motrix public APIs and cold-audited against native metadata; selected rows are committed through disjoint native indices while unsupported semantics fail closed. |
| MJWarp | The MuJoCo composition profile plus CUDA per-world variant fields and named compiled geometry. | One model/data runtime uploads selected values in place, restores persistent channels and forwards the main Data; no selective native forward is claimed. |
| Drake | No-variant MJCF fixed/floating physical entities, passive joints and fixed rigid static bodies. | One expanded portable model is cold-audited against public layout metadata; selected resets submit coherent complete rows and unsupported variants, mirrors and control restoration fail closed. |
| Newton | Bounded portable MJCF entities with fixed/floating roots, passive/static bodies, same-layout same-shape-type variants and named found contacts. | Independent per-variant builders are assigned to explicit worlds; public per-entity articulation views and native identity audits isolate selected state resets and contact-world attribution while unsupported mirrors and mixed shape types fail closed. |
| Genesis | Bounded CPU-profile portable MJCF fixed/floating/passive/static entities and single-link rigid heterogeneous variants. | Independent native entities are bound by audited public names and addresses; selected state/reset rows preserve unrelated state, and any non-balanced native variant assignment or unsupported sensor/DR/contact-mask mapping fails closed. |
| IsaacGym | Standalone MJCF entities, scalar joints, position drives, rigid mirrors and immutable arbitrary assignment. | Queried actor/body/DoF indices are audited; indexed writes are unioned until the next step and descendant body reads advertise their freshness boundary. |
| IsaacSim | Articulation/rigid views, scalar joints, immutable same-drive K-prototype assignment, one-body rigid objects, geometry readback, selected friction mutation, mapped collision-pair force sensors and staged world-frame body wrenches. | Prim/view, assignment, body/joint maps, native body/geometry properties and selected sphere radii are audited; selected material writes read back native current rows, preserve omitted channels/environments, and failures after submission fault the worker. |

## Validation

`tests/contract/test_worker_scene_native.py` enables real factory-to-worker acceptance with `UNISIM_TEST_ISAACGYM_SCENE=1` or `UNISIM_TEST_ISAACSIM_SCENE=1`. Tests include both backends' N5/K2 non-round-robin identity, nq/nv/nu, partial reset isolation and persistence, keyframe control distinct from qpos, complete-scene playback and a versioned import report. Worker-specific suites add independent native mass/COM/inertia, topology, mirror, passive-articulation and filtered contact-force checks; the IsaacSim gate also reads native geometry identity, collision state and PhysX materials—including multiple collision prims on one body—plus selected native sphere radii from spawned visual USD, and exercises force, torque, consumption, selected-reset wrench behavior, per-substep callback state/wrench composition, selected friction mutation with native readback and physical response, reset-time body-mass fail-closed behavior, and cold/warm raw- and role-USD cache hits with native readback and cached-file immutability. The final #72 test drives one MJCF-only robot/object/table/mirror operation scene through public construction, layout, property, contact, reset, substep-control, wrench and playback checks in MuJoCo and gated IsaacSim, recording runtime/GPU evidence and excluding #133 camera/RGB. A skipped IsaacSim test is not native evidence.

The Newton native gate is the real-CUDA `tests/adapters/newton/test_multi_entity_feasibility.py`. Its N5/K2 `[1,1,0,1,0]` assignment covers a controlled fixed-root robot, passive floating objects and a static table; it verifies per-world mass/COM/inertia/shape identity and persistence, source defaults, object-only and joint-only selected reset isolation, unrelated control preservation, full selected snapshots across the static zero-width view, nonidentity orientation and offset-COM frame conversion, passive action width, actuator force response, variant-dependent mass/inertia force response under identical geometry, source-order address permutation, independent N1-versus-N5 parity, per-variant playback paths during backend lifetime, generated-source cleanup after close, real contact-world isolation, and deterministic rejection of mixed shape-type variants and kinematic mirrors before solver construction. This is acceptance evidence for the bounded profile above, not a claim of arbitrary topology, renderer equivalence, keyframe control restoration, or throughput optimization.

The recorded native evidence uses Newton 1.5.1, Warp 1.16.0 and MuJoCo 3.11.0 on an NVIDIA GeForce RTX 4090.

Genesis portable-entity acceptance is the real native CPU test `tests/adapters/genesis/test_portable_entities.py`. Its N5/K2 `[0,0,0,1,1]` assignment covers a controlled fixed-root robot, floating passive articulation, heterogeneous rigid object and fixed static table; it verifies public layout dimensions and actuator width, binding through actual native link names/IDs, native variant masses `[0.5,0.5,0.5,1.5,1.5]`, public geometry names/IDs/body ownership, active native visual instances and their source AABBs, selected state isolation, selected reset isolation, source variant inertia records, a physical joint-control response and heterogeneous free-body rotational response. The recorded runtime is Genesis 1.3.3, Torch 2.14.0+cpu and Quadrants 1.3.0; this is CPU evidence and makes no GPU claim. A skipped Genesis test is not native evidence.

Motrix portable-entity acceptance is the real native test `tests/adapters/motrix/test_portable_entities.py`. It covers duplicated local names, two floating roots, passive-joint physical response, public/native body and geom maps, subtree IDs, native mass and COM readback, selected reset isolation with controls preserved, passive joint reset, unsupported-profile rejection and composed-source cleanup. Recorded local evidence uses Python 3.13.14, MotrixSim Core 0.8.2, MuJoCo 3.11.0 and NumPy 2.5.2; a skipped Motrix test is not native evidence.

The existing `model_file` entry point retains its cold importer and source settings, then adopts the initialized native objects into the same scene executor as explicit entities. `LegacySlotProjection` preserves historical root/state/control buffer shapes and names; it contains no physics loop. Both workers now have one step, reset and refresh implementation. Old D-wide actions (including passive columns) and synthetic 7/6 root coordinates remain an explicit compatibility projection, not a claim about authored free joints or actuator ownership. Gym's historical COM linear-velocity outputs and world angular-velocity root slot are translated separately from canonical link/body-frame coordinates. Existing ground/importer policies are retained on the cold source path; no new SDK dependency is added to the legacy Isaac host.

Drake portable-entity acceptance covers duplicated local names, two floating roots, passive-joint visibility and physical response, selected reset isolation, N5 batch rows versus independent N1 runtimes, reversed declaration order, pre-materialization rejection of unsupported variants/mirrors, and cleanup on close or cold layout mismatch. A skipped Drake test is not native evidence.
