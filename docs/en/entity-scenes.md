# Entity scene execution

[English](entity-scenes.md) | [中文](../zh/entity-scenes.md)

This page describes how adapters execute the public entity, immutable identity and selected-reset contracts defined by the [entity decision](adr-entities.md). The cold authoring/compilation boundary is defined by the [portable MJCF decision](adr-portable-mjcf.md). MuJoCo-family adapters compile and execute complete scenes; Isaac adapters retain their dedicated workers and native execution.

Legacy compiled MuJoCo/MJWarp scenes use the same cold `CompiledModelIndex` audit internally. It records native body partitions, roots, joint qpos/qvel addresses, mocap addresses and actuator transmission/control columns without renaming anonymous objects or pretending tendon/site/root transmissions are scalar joint actuators. Old whole-model APIs retain their source semantics; the restricted entity layout is only exposed when its partition cross-check passes.

## Source preparation and identity

The common portable MJCF compiler validates sources, defaults, names, referenced resources and same-layout variants; produces expanded MJCF, frozen `CompiledSceneLayout`, source/intent report and content identity. Standalone worker assets receive explicit compiler-derived body inertials and joint limits. Geometry names, body ownership, source contact masks, source friction and sphere radii also travel in the cold-path intent table, preserving each body's source geom order. Actuators are removed from exported XML after their unit-gear position-drive intent has been validated and copied into a separate table; the native MJCF importers cannot safely consume MuJoCo's canonical general-actuator spelling. Source passive joint damping/springs, activation state, unsupported transmissions and non-scalar joints fail closed in this profile. Compiled per-environment actuator control limits apply to step targets and initial/full-reset controls; unlimited controls are not clamped to a stored zero range.

Cross-entity sensor declarations live in a scene-level sensor-only `fragment_files` entry. Portable identity includes fragment bytes. Fragments may declare ordered geom-pair contact forms, world-referenced body/site `FramePos`/`FrameQuat` forms, or world-referenced qualified-body/site `FrameLinVel`/`FrameAngVel` forms with final qualified names; MuJoCo retains them in the expanded MJCF, mapped IsaacSim consumes the force/netforce contact form through `ContactSensor` filters, Motrix consumes both audited contact forms, audited body/site-pose forms and audited qualified-body/site motion forms, and Genesis consumes audited qualified-site/qualified-body pose and motion forms plus both bounded cross-entity geom-pair contact forms.

Generated filenames use safe internal USD identifiers; they do not define public entity identity. Post-compilation edits are serialized from the current spec, avoiding stale last-compiled XML. The host retains the generated full scenes and standalone sources until worker shutdown. Worker-returned entity names, complete assignment and actual instance masses are checked against compiled intent. Worker audits additionally establish native topology, drive, inertia and selected visual sphere-radius adoption. Echo alone is not an independent asset identity proof.

Newton consumes the portable compiler's complete per-variant MJCF files rather than homogeneous template replication. It imports each source into an independent public `ModelBuilder`, assigns the selected source to each `begin_world()` world, and binds one public `ArticulationView` per physical entity. Cold-path audits compare the effective per-world gravity, masses, COMs, inertia tensors, shape types and shape dimensions against each selected source before solver construction. The bounded profile covers multiple articulations and multiple free roots per world, fixed roots, passive entities, static rigid entities, same-layout same-shape-type heterogeneous variants and force response, selected entity reset/playback, and named geom-pair found sensors with per-world attribution. Kinematic mirrors and mixed shape-type assignments fail closed.

Portable Newton selected resets preserve unrelated state and controls, clear the selected entity's controls, and fail closed for `restore_default_controls`. Keyframe/default control restoration is not claimed.

The host publishes separate nq/nv/nu and entity root layouts. Public root state uses link-origin position/linear velocity, wxyz quaternion and world angular velocity with clone offsets removed exactly once by the adapter. Full generalized qvel retains body-frame angular velocity. Passive joints contribute state but no implicit action columns.

## Reset and control

All entity patches are validated before materializing or writing native state. Prepared rows and explicit masks pass through one versioned reset command. Existing full qpos/qvel writes on the new entity entry point normalize into the same patch submission. Full `reset()` restores each selected environment's variant defaults and independent keyframe control; controls need not equal joint positions. Other environments and unselected entities retain their state and targets.

IsaacGym accumulates indexed root/DoF submissions until the next physics step, because a second indexed setter can otherwise overwrite an earlier reset. Native COM velocity is converted at both directions of the public link-origin boundary. Root and joint state is available immediately; articulation descendant body/sensor state after initialization or affected resets is explicitly unavailable until the next step. The host refuses those reads instead of presenting stale values as current. The legacy model-file path behaves differently: PhysX cannot refresh link poses without stepping, so between an INIT keyframe or `set_state` and the first physics step the worker overlays exact MJCF forward kinematics onto freshly written environments — positions, orientations and link-origin/angular velocities computed from the effective generalized state — and clears their stale contact-force rows. The host scans the kinematic tree into the INIT payload (per variant under fixed variants) and fails closed when it disagrees with the adopted public body/joint layout. Legacy reset input follows the canonical generalized-velocity contract (world link-origin linear velocity, body-frame angular velocity); the historical COM-velocity projection is retained only on the published legacy output buffers.

Unrecoverable native commit failures set the worker fault marker and the host refuses further state or step use. Validation failures before native submission preserve the session. Shared-memory slot shapes/dtypes are checked before attachment, including zero-width action or state layouts.

## Inspection and playback

Versioned worker configuration reports are required and checked before being accepted. Entity assignment, body masses and geometry have scoped records distinguishing source intent from instance readback; source values never stand in for missing runtime fields. For a mapped IsaacSim scene, INIT validates the native mass, COM and geometry records, then `get_body_mass()` returns a detached `(num_envs, nbody)` table by scattering those worker-native snapshots into frozen public body order. Unowned public rows retain their canonical compiled-source values; reset-time mutation then replaces the corresponding current rows (see below). `get_body_ipos()` returns the detached canonical compiled-source default of shape `(nbody, 3)`, while `get_body_ipos(env_ids=...)` returns detached worker-native materialization rows of shape `(len(env_ids), nbody, 3)`, preserving empty, duplicate and reordered selections. Public geometry is ordered by frozen entity/geom records: `get_geom_names()` returns qualified names, `get_geom_body_ids()` returns their public owning body IDs, `get_geom_contact_masks()` reports normalized native collider enablement as matching contype/conaffinity rows, and `get_geom_friction()` returns detached worker-native PhysX material rows of shape `(num_envs, ngeom, 3)` as `[static, dynamic, 0]`. Initial materials follow immutable variant assignment; selected resets may replace current material rows, and an ordinary state reset does not silently restore them. Collision state remains role-immutable. The worker reads identity and materials from actual spawned collision prims and rejects count, name, ownership, mask or material drift. The separate visual `Sphere.radius` audit remains a bounded sphere-profile check, not a dimension API.

Mapped `set_state()` accepts the existing `ResetRandomizationPayload` for selected-environment property writes. Supported terms are positive `body_mass`, `body_ipos`, positive diagonal `body_inertia` (the principal-axes orientation stays the environment's immutable assigned-variant `body_iquat`), Coulomb `geom_friction`, actuator `kp`/`kd` drive gains, and nonnegative `dof_damping`/`dof_armature`/`dof_frictionloss` joint tables; `base_mass_delta`/`base_com_offset` are folded host-side into the primary entity's root-body rows. Every table is an absolute dense public-layout table in frozen public column order and must be finite; friction requires nonnegative values with `static == dynamic` and an exact zero third column, and free-root DOF columns must stay zero because PhysX exposes no root joint damping/armature/friction. Columns owned by kinematic mirror entities or by no entity must equal their variant or canonical defaults. The command reuses `RESET_ENTITIES`, writes through the mapped public PhysX views (rigid-body mass/COM/inertia views, per-row articulation drive and DOF setters, material views), reads native values back after the write, verifies selected rows against the request and untouched rows against the pre-write snapshot, refreshes host current-value getters, and faults the worker on a native write/readback failure. Drive `kd` composes additively with natural `dof_damping` into the single PhysX joint-damping slot; the worker tracks both channels so repeated resets stay exact. Gravity remains unsupported because it is simulation-global rather than selected-environment state; inertial orientation, geometry dimensions and solver contact parameters fail closed with explicit per-term reasons. The versioned import report describes materialization and must not be treated as post-reset current-value readback. Complete selected-environment scene sources are returned for playback, retaining robot, object, table and mirror. Native rendering remains worker-owned; mapped-worker physics snapshot export is not yet exposed by this slice.

The current native camera profile captures the first entity in environment 0 with its existing tracking behavior. Only `cam_distance`, `cam_elevation` and `cam_azimuth` configure capture. Nondefault `cam_lookat`, `cam_tracking`, `cam_tracking_env_idx`, `cam_tracking_extra_envs` or `cam_fov` raise `NotImplementedError` before worker access, including repeated renderer initialization. Default `CameraCfg` values retain the existing native view; they do not select the MuJoCo grid camera. Interactive viewers also reject custom spherical offsets, because their view is controlled by the native viewer. Returning the complete source for any selected environment does not imply that native cameras can select that environment.

IsaacSim maps immutable assignments by converting K unique prototypes and copying the selected prototype to each exact environment path. Assignment is fixed at construction and is never resampled. Variants must share one public layout and identical effort limits, armature and joint friction, but drive stiffness/damping (`kp`/`kd`) may differ per variant: initialization rewrites every environment's assigned variant gains through the per-row PhysX view setters, and the post-init audit compares native gains against each environment's assigned variant. One-body rigid views, fixed-root mode, environment view-row mapping, mass/COM/inertia and selected visual sphere radii are audited; topology, drive, and source-format limits still fail closed. The common host only enables the documented MJCF scalar-joint profiles, not URDF or all PhysX asset features.

IsaacSim caches two immutable cold-path USD stages. The raw cache stores expanded-MJCF-to-raw-USD converter output under `~/.cache/unisim/isaacsim/raw-usd`; set `UNISIM_ISAACSIM_RAW_USD_CACHE` to an absolute path, or use the read-only legacy fallback `UNILAB_ISAACSIM_RAW_USD_CACHE`. Raw identity extends the portable scene content identity with the expanded source digest, importer parameters, IsaacSim/IsaacLab/MJCF-importer/Python versions, entity, and variant. The role cache stores independently baked USD under `~/.cache/unisim/isaacsim/role-usd`; set `UNISIM_ISAACSIM_ROLE_USD_CACHE` to an absolute path, or use the read-only legacy fallback `UNILAB_ISAACSIM_ROLE_USD_CACHE`. An empty value or `0`, `false`, `no`, `off`, `none`, or `disabled` (case-insensitive) disables either cache independently. Role identity extends the raw identity and immutable raw-artifact fingerprint with the source/role entity, variant, kind, root mode, collision/mirror settings, and bake parameters. Hits validate the complete manifest, file inventory, sizes, and SHA-256 digests; conversion and bake output is staged and atomically published, while malformed, interrupted, or corrupted entries are treated as misses and replaced. A role miss copies the complete raw artifact before baking. A role hit re-reads variant metadata, native body paths, articulation/rigid topology, mobility, gravity, collision, and disabled converter drives before native materialization, prim/view construction, parameter readback, capability checks, and effective-report validation. Disabling the role cache still produces an independent temporary copy per role, so role edits never mutate cached raw USD or another role.

Mapped IsaacSim scenes serve `<contact data="force" reduce="netforce"/>` through IsaacLab `ContactSensor` filters. The value is the filtered normal contact force in newtons, expressed as a world-frame 3-vector on the `geom1` source body due to the `geom2` target body; IsaacLab sums the contact points. `get_sensor_data()` returns the final completed physics substep, does not average substeps, returns zero when that pair has no contact, and reset clears stale rows. Body-net `data="found"` and unsupported reductions fail closed. The legacy reserved body-net slot is never exposed as a pair query. SDK-free checks pin the declaration, wire, row mapping and reset semantics; the gated real-worker suite checks static 1 kg and 2 kg support forces.

Mapped IsaacSim also supports world-frame `body_force` and `body_torque` interval wrenches at the native body COM. Submissions accumulate until the next step, apply for every requested substep, and are consumed afterward. Entity resets clear the selected entity bodies and full resets clear every staged body row. A mapped scene also accepts the existing host-owned `set_pre_step_control()` callback: the host issues one worker STEP per public substep and refreshes shared state before each callback. Callback control and dynamic wrenches are recomposed from scratch, compose additively with the staged interval wrench, and are consumed when the step call finishes. This is a correctness host loop, not the device-resident controller or performance path tracked by #152; legacy model-file callbacks remain unsupported.

## Drake bounded portable profile

Drake consumes the common portable compiler's expanded MJCF and accepts its layout only after public DrakeUni model information and body lookups agree with the frozen `CompiledSceneLayout`: dimensions, global body names and IDs, every root and scalar-joint qpos/qvel mapping, complete joint consumption, actuator names/order, and actuator target addresses all bind exactly. Fixed roots are read through public body-state queries; floating roots use generalized-state snapshots. Passive joints contribute state and velocity but no implicit control columns.

Selected entity resets snapshot the complete scene state, apply already validated patches, and submit complete coherent rows through public DrakeUni reset. Unselected entities and environments preserve their state. A native reset failure faults the backend. `restore_default_controls=True` is rejected before mutation because DrakeUni reset does not preserve an explicit control-restore contract. Entity mode also rejects implicit single-root base/body-frame helpers.

This Drake profile supports no-variant MJCF physical entities and assigned same-layout fixed variants with fixed or floating roots, passive scalar joints, and fixed rigid static bodies. A no-variant scene uses one expanded portable model. A fixed-variant plan creates one DrakeUni runtime for each **used** variant and assigns only that variant's public environment rows; step, reset, sensor, and body-state traffic is explicitly scattered and gathered between public and local rows. Used variants must retain identical control and sensor metadata, and construction compares joint/actuator addresses, control limits, ranges, gains, sensors, and dimensions before exposing the backend.

Fixed-variant acceptance is based on actual public DrakeUni `native_model_properties()` readback: body order, mass, COM, body-origin inertia, collision-geometry order/ownership/type, and native primitive parameters must match each compiled source within strict tolerances. Unsupported primitive identities, mesh/convex identity, kinematic mirrors, other variant layouts, and `restore_default_controls=True` fail closed. `get_playback_model()` requires an explicit environment index for a multi-variant plan and returns that row's immutable generated model. No throughput optimization is claimed.

Native Drake acceptance is mandatory for a support claim; optional tests skip when the Drake native batch extension is unavailable. DrakeUni must contain both the multi-entity layout-ordering fix and public native model-property readback. The current released `drake-uni==0.1.0` predates these prerequisites, and ordinary CI does not provide native Drake evidence.

## Genesis bounded portable profile

Genesis uses the common portable compiler as its layout, identity, provenance and source-relationship authority. The adapter normalizes each source through the common loader, serializes independent Genesis-owned MJCF inputs, and adds each public entity separately to one native `Scene`. Materialization accepts a physical entity only when its native state dimensions, actual link names, native inertia matrices, joint addresses, actuator order and PD gains match the independently compiled source; binding never assumes Genesis link order. Public qpos/qvel, body and actuator columns are then scattered to their owning entities, while passive entities contribute state but no control columns. A collision-disabled mirror of a physical source is materialized with Genesis' public `Kinematic` material: its topology and fixed-variant visual identity are audited, but it has zero qpos/DoFs and owns no collision geometry, so physical inertia or mass identity is not claimed for the mirror.

The first profile covers fixed-root articulations, floating passive articulations, floating heterogeneous rigid objects, fixed static rigid bodies and collision-disabled visual mirrors of physical sources. Heterogeneous variants are restricted to one-link rigid entities. Because Genesis 1.3.3 assigns an iterable of MJCF morphs itself, construction accepts only the exact public balanced mapping expected from that native behavior—K variants over N environments dispatch as contiguous blocks, with the first remainder-sized block receiving one extra environment. For N5/K2 this is `[0,0,0,1,1]`; `[1,1,0,1,0]` is rejected before Genesis scene construction. This owner-side mapping check is independent of Genesis' private solver helpers.

Construction freezes portable defaults from each normalized source. When `default_keyframe_name` is configured and resolves in a source, only that source key's scalar hinge/slide qpos/qvel and actuator controls are overlaid through public per-entity Genesis APIs. If a source lacks the selected key, its normalized scalar qpos is retained and qvel/controls remain zero. Raw source-keyframe root pose and root velocity are ignored: the declared portable native-construction root placement is retained and default root velocity remains zero. Genesis 1.3.3 has no persistent public control-target getter; the cold default table and public submission routing are the acceptance boundary.

Selected `set_state()` and `reset_entities()` submit only selected rows to the owning native entities, preserving unrelated entities and environments. A partial native state-submission failure faults the backend. On selected entity reset, `restore_default_controls=False` clears that entity's selected control rows, while `restore_default_controls=True` restores its assignment-aware default control columns; unrelated rows and entities remain untouched. Portable selected-row reset randomization is bounded to `body_mass`, `base_mass_delta`, `body_ipos`, `base_com_offset`, `dof_damping`, `dof_frictionloss`, `dof_armature` and actuator `kp`/`kd`: public columns are prevalidated, split through audited owning entities, submitted with public native setters, and partial native failure faults the backend. Mass and COM channels are independent, and absolute public COM values are converted to Genesis local COM shifts from immutable variant-assigned defaults. Other reset-randomization terms and reset-time body-force mapping fail closed. Selected mirror roots are state-only: public world-frame `set_pos(..., envs_idx=...)` and `set_quat(..., envs_idx=...)` submit selected pose rows, and full reset restores each mirror's independent declared default. Mirror mass, inertia, COM/DOF/actuator mutation and body wrenches have no native physical owner and fail closed. Physical (non-mirror) kinematic entities and the legacy single-primary-DoF view also remain unsupported. Declared fixed-root and floating-root world placement is passed through the public MJCF morph position/quaternion arguments because native Genesis does not retain the normalized root placement as the free-joint default during this import path.

Portable geometry exposes frozen qualified names, public IDs, owning body IDs, bounded Genesis-native geometry sizes, contact masks, friction coefficients and contact solver parameters. Construction audits every source variant's named native visual instance by name, owning link, exact active environment rows and reviewed source AABB bounds; current visual-identity support is limited to spheres and boxes, while unsupported geometry types and ambiguous or missing native identity fail closed. Geometry sizes are derived from those audited native AABBs: spheres expose their native radius and boxes expose native half-extents in frozen public order; non-uniform fixed-variant sizes fail closed. `get_geom_contact_masks()`, `get_geom_friction()`, `get_geom_solref()` and `get_geom_solimp()` aggregate only exact collision instances by name, owning link and active environment rows in frozen public order. A visual mirror contributes public zero contact masks from its physics/collision-exempt public Kinematic boundary, but has no native collision identity for friction, solver parameters or contact fragments. Masks are Genesis' recoded native values, not MuJoCo table echoes; friction columns are Genesis' public native coefficient order `[sliding, torsional, rolling]`, not a static/dynamic material table. Genesis' native seven-value solver table is split at the public boundary into MuJoCo-compatible `solref = [timeconst, dampratio]` and `solimp = [dmin, dmax, width, mid, power]`; importer preprocessing or defaults are therefore reported as actual native values, not echoed source XML. These are construction-time property reads, not reset mutation or solver-feature enablement claims. Absent or ambiguous collision identity and non-uniform fixed-variant masks, friction or solver parameters fail closed. Other geometry properties remain unsupported. Each physical source's native link inertia matrices are checked against the compiled diagonal inertia and orientation, but arbitrary inertia readback is not exposed. Heterogeneous inertia records plus free-body response provide bounded native evidence; because the acceptance variants also differ in mass, COM and radius, that response does not isolate inertia alone.

Native variant mass is read through the public Genesis mass getter and scattered into frozen public body rows; selected-environment `get_body_ipos(env_ids=...)` exposes variant COM rows, while no-argument `get_body_ipos()` remains the canonical `(nbody, 3)` default table. Successful mass or COM randomization updates the corresponding effective per-row host cache only after every native submission succeeds; source/variant defaults remain the randomization baseline rather than a previous randomized value. Genesis 1.3.3 exposes COM mutation through public `RigidEntity.set_COM_shift(...)` but has no entity-level COM-shift getter, so the runtime boundary is the audited setter plus the host cache; native solver readback is used only as explicit test evidence, never by backend runtime code.

Portable DOF readback exposes Genesis' public native `get_dofs_damping()`, `get_dofs_frictionloss()` and `get_dofs_armature()` tables through the already-audited joint/native qvel address mapping. Construction captures every active-environment row, rejects non-uniform rows within one fixed variant, and the public DOF getters return one detached cold-default `(nv,)` table only when all fixed variants agree. Selected-row reset randomization routes exact `(rows, nv)` public tables through the owning entities' public `set_dofs_damping(...)`, `set_dofs_frictionloss(...)` and `set_dofs_armature(...)` APIs; native public readback is the acceptance evidence, while the no-argument backend getters remain cold defaults rather than per-environment current-value mirrors. Passive joint damping, friction loss and armature remain distinct from imported position-drive `kp`/`kv`, and restoration is not claimed.

Portable source sensors accept only entity-owned, unreferenced site `framepos`, `framequat`, `gyro`, `velocimeter` and identity-orientation `accelerometer` declarations. Sites must be named, belong to the same public entity, use the dimensions required by their type, and have identical complete sensor identity across every fixed variant; public names are owner-qualified. Genesis does not import MJCF sensors, so pose/motion rows are computed from public native link state plus the audited site-local pose: pose getters supply the source/user body frame and public velocity getters supply world-frame link-origin motion. Accelerometers create one clean public native IMU at the audited entity/link/site offset; their proper linear acceleration is the completed-step native sensor reading, not a synthesized state-mutate result. The public `framequat` order is Genesis/MuJoCo-compatible wxyz. Referenced frames, rotated accelerometers, contact sensors and all other source-sensor forms fail closed.

Scene-level qualified-site fragments accept only world-referenced `framepos`, `framequat`, `framelinvel` and `frameangvel` declarations against final qualified public site names. Their complete site identity must be identical across every composed fixed variant; pose reads use the same audited public native link/source-frame and site-local pose computation as entity-owned site-pose sensors. `FrameLinVel` is world-frame site-point velocity (public native link-origin velocity plus world angular velocity crossed with the rotated site offset), and `FrameAngVel` is public native world angular velocity. This world-frame result is deliberately different from entity-owned site `velocimeter`/`gyro` readings in their audited site frame. Referenced forms, site accelerometers, entity-owned frame-motion declarations and all other site-fragment forms fail closed.

Scene-level body-frame fragments accept only world-referenced `framepos`, `framequat`, `framelinvel` and `frameangvel` declarations that name their exact final qualified public body. MuJoCo body frame sensors report the inertial body frame, so Genesis composes its audited public native link-origin pose with the assignment-selected source body inertial position/orientation. Motion uses the public native world link-origin linear/angular velocity: `FrameAngVel` returns angular velocity directly, while `FrameLinVel` evaluates the inertial-frame origin as link-origin velocity plus world angular velocity crossed with the rotated source `body_ipos`. Fixed variants must retain the complete body-sensor identity; source inertial metadata supplies the variant inertial identity. Entity-owned body sensors, referenced forms and all other body-fragment forms fail closed. Genesis' native inertia audit also rejects a source inertial-orientation mismatch rather than presenting a mis-framed body frame.

Scene-level cross-entity geom-pair contact fragments accept only `data="found" num="1"` and `data="force" reduce="netforce"` declarations. Genesis binds each public geom to the exact native collision instance selected by name, owning link and active-environment rows, routes those IDs by fixed-variant assignment, and matches Genesis' public batched `get_contacts()` geom IDs and valid mask as an unordered pair. Found flags describe the latest completed physics step. Netforce reads the public `force_a`/`force_b` tensors, selects the force applied to authored `geom1` according to the exact native geom order, sums all exact valid contact slots, and returns the completed-step world-frame three-vector on `geom1` due to `geom2`; selected state/reset rows remain zero until their next completed step. Same-entity pairs, source contact sensors, absent or ambiguous collision identity and all other contact forms fail closed.

Portable `apply_body_force()` maps each audited public owned-body ID to its owning entity's global Genesis solver link. The public world/unowned body `0` exists only for layout consistency and is rejected as a wrench target. Forces and torques are world-frame vectors applied through the public `RigidSolver.apply_links_external_force(..., ref="link_com", local=False)` and `RigidSolver.apply_links_external_torque(..., ref="link_com", local=False)` APIs; force acts at the target link COM. Repeated direct submissions and ops within one interval plan accumulate each channel independently for the upcoming native `Scene.step()`; Genesis applies those wrenches throughout the solver call's internal substeps and clears native external forces and torques at its end. The backend clears its pending host bookkeeping only after a successful physics substep. A later interval plan first cancels prior pending staging, selected `set_state()` rows cancel all pending bodies in those rows, and selected `reset_entities()` rows cancel every body owned by each selected entity while unrelated pending wrenches persist. Native submission or cancellation failure faults the backend, and callback-time staging is rejected. Arbitrary application points, dynamic callback wrenches and reset-time body-wrench randomization remain unsupported.

## Motrix bounded portable profile

Motrix imports the common compiler's complete expanded multi-root MJCF through the public `msd.from_file()` and `msd.build()` APIs. Construction accepts entity mode only after actual Motrix metadata agrees with the frozen `CompiledSceneLayout`: qpos/qvel/actuator dimensions, native link names, floating-root and scalar-joint state addresses, complete generalized-state ordering, actuator names/order/targets, and geom names/order. Variant contexts additionally audit native body/geom order, public control and joint limits, actuator gains and geom friction, capture actual native geometry sizes, and read back construction mass and COM. Public body and geom IDs scatter through those audited native maps rather than assuming Motrix link or geom order.

The first profile covers no-variant and immutable same-layout fixed-variant fixed/floating physical entities, passive scalar joints, fixed rigid static bodies and collision-disabled kinematic mirror roots. Motrix creates one native model/data context per used variant and explicitly scatters and gathers public qpos/qvel, controls, selected reset rows, step execution and link pose/velocity rows by immutable assignment. Before runtime mutation, each context captures native construction controls—or the uniquely named native default-keyframe `ctrl` record when `default_keyframe_name` is configured—and clamps them to the audited native control limits. It also applies the selected keyframe's public `dof_pos`/`dof_vel` through `Keyframe.apply()` before the construction forward-kinematics pass, making that key state the context's construction/full-reset default. Variant geometry, mass, COM and inertia may differ; `get_body_mass()` exposes per-environment native rows, selected-environment `get_body_ipos()` exposes native COM rows, and audited native geometry records retain actual per-source sizes. Motrix does not expose inertia readback, so the native acceptance applies equal scalar-joint torque and verifies distinct effective response rather than pretending that a getter exists. It also does not expose actuator activation state, so activation-bearing portable scenes fail closed rather than silently zeroing activation. Non-uniform public control/joint limits, actuator gains or geom friction fail closed because the public APIs expose canonical scalar tables. `apply_body_force()` maps world-frame public body-force and optional body-torque rows into every owning variant context through the audited public `Link` APIs: submissions accumulate additively for the upcoming native step and are consumed then, selected root/joint resets cancel only the impacted entity body rows, and unrelated pending wrenches persist. A runtime without either required native API fails closed.

Mirror roots must materialize as public native mocap bodies. Construction audits the complete mirror body/mocap identity across fixed variants and requires every imported mirror geom's public collision group and affinity to be zero. Selected-row mirror pose writes convert public wxyz roots to Motrix xyzw mocap poses and submit through public `Mocap.set_pose()` on the owning variant's disjoint data slice; unrelated rows and entities remain untouched. Full selected-environment reset restores the mirror's independent declared/default pose. Physical (non-mirror) kinematic entities remain unsupported.

With `add_body_sensors=True`, Motrix resolves `base_name` against the frozen public body layout before variant materialization: a qualified `entity/body` name must match exactly and a local name must match exactly one public body. Each native variant then receives generated Motrix frame-position and frame-quaternion sensors for every public body. Construction requires exactly two sensors per public body, identical names across variants, and consistent native row/dimension reads. Public sensor getters gather rows from the owning immutable variant context; batch reads flatten and concatenate each sensor in request order. Native quaternions remain xyzw in `get_sensor_data()`, while `get_body_quat_b()` applies the public wxyz conversion. Selected resets refresh derived frame sensors without submitting unrelated generalized-state rows.

Authored source and scene-level fragment frame sensors are accepted only as world-referenced Motrix `FramePos` or `FrameQuat` sensors on a public body or uniquely qualified public site. Entity-owned source names retain their owner prefix and may target only a site in that same entity; fragment names are unprefixed and target final public body/site names. The common compiler freezes their public names, types, dimensions and object references across variants; Motrix materialization additionally requires a complete named sensor set, matching native frame-sensor type/body-or-site object/reference identity, exact native row dimensions, and identical names across fixed variants. These `FramePos` reads expose world-frame positions and `FrameQuat` retains native xyzw output. They can be mixed with generated tracking sensors and are gathered through the owning immutable variant context.

Scene-level site-motion fragments accept only world-referenced qualified-site `FrameLinVel` and `FrameAngVel` declarations. The common compiler freezes their qualified-site target and sensor identity; Motrix audits the native frame-sensor type, site object, world reference, exact dimensions and complete native site parent/local-pose identity before construction, then gathers public rows through the owning immutable variant contexts. `FrameLinVel` reports world-frame site-point velocity and `FrameAngVel` reports world angular velocity. Native acceptance compares both values with the public world-site Jacobian evaluated at the actual public qvel after world root-velocity conversion. Entity-owned frame motion, referenced forms and all other site-fragment forms fail closed.

Scene-level body-motion fragments accept only world-referenced qualified-body `FrameLinVel` and `FrameAngVel` declarations. The common compiler freezes their qualified-body target and sensor identity; Motrix audits the native frame-sensor type, body object, world reference and exact dimensions before construction, and gathers public rows through the owning immutable variant contexts. `FrameLinVel` reports world velocity at the inertial body-frame origin (the public world body-origin velocity plus world angular velocity crossed with the rotated native `body_ipos`), while `FrameAngVel` reports world angular velocity. Entity-owned body motion, referenced forms and all other body-fragment forms fail closed.

Entity-owned source site motion sensors additionally accept only unreferenced `velocimeter` and `gyro` declarations on a named site in the same entity. Motrix must materialize them as native `FrameLinVel(local)` and `FrameAngVel(local)` sensors with exact dimensions, and fixed variants must retain identical complete identity. Their values are the native site-frame motion vectors: native acceptance compares them with the public world-site Jacobian result rotated into the audited site frame. Accelerometers, referenced sensors and entity-owned frame-motion declarations fail closed.

Scene-level geom-pair contact fragments use the common `data="force" reduce="netforce"` and `data="found" num="1"` forms only. Motrix audits each native contact sensor's exact geom pair, reduction mode, and force/found report flags before construction, requires exact native dimensions and identical names across fixed variants, and returns the values left in native sensor storage after a completed step. Unsupported contact reductions and other site-sensor forms fail closed.

Portable `get_site_jacobian_w()` resolves qualified site names to native site IDs and returns Motrix' world-frame compact Jacobian as public `jacp`/`jacr` tensors. Fixed variants require the same complete set of unique non-empty site names plus identical selected-site parent and affected-DoF identity; rows are gathered from each owning native variant context, and requested columns are selected in frozen public qvel order. Invalid public DoF ranges, DoFs absent from a site path, missing/duplicate/ambiguous site identity, malformed native shapes, and nonfinite values fail closed. This is a Jacobian read only; it does not add site sensor support.

Portable `set_state()` selected-row reset randomization is bounded to `body_mass`, `base_mass_delta`, `body_ipos`, `base_com_offset`, `dof_armature` and `dof_frictionloss`. Public body columns are prevalidated against exact shape, finite values and native-link mapping before state submission; values are then applied through public Link mass and COM overrides on the owning variant `SceneData[DisjointIndices]` slices. Public DOF tables are prevalidated against exact shape, finite non-negative values and audited native scalar hinge/slide joints; selected rows are then applied through public Joint armature and friction-loss overrides on those slices. Unmapped and free-root public DOF columns remain their variant defaults and reject mutation. Native public override readback is the acceptance evidence, omitted mass/COM/DOF channels are independent, defaults remain detached, and a partial native submission faults the backend. Motrix 0.8.2 exposes no public runtime joint-damping override, so `dof_damping`, actuator gains and all other reset-randomization terms remain unsupported. Selected `reset_entities()` rows are submitted coherently through `SceneData[DisjointIndices]` without a whole-scene reset, preserving omitted channels, unrelated entities, unrelated environments and current controls. With `restore_default_controls=True`, only controls impacted by the selected entity's root or joint patch are restored from that variant's cold-captured native defaults; unrelated control columns and rows persist. Full `reset()` submits each selected environment's complete variant default qpos/qvel, default kinematic mirror pose and default controls, preserving unrelated environments and clearing all pending body forces/torques for reset rows. A partial native state submission faults the backend. Other fixed-variant layouts, physical kinematic entities, other source sensor forms, other site-sensor forms, unsupported contact forms, generated terrain, other reset randomization, fixed-variant native playback/rendering and non-uniform public geometry-size reads fail closed. Fixed-link mass may read as zero because public mass/COM values are effective native readback, not echoes of source inertial elements.
