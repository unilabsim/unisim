# Architecture

MJWarp body getters and generalized-state getters share the same boundary after `step()` returns, for both callback and callback-free paths. The first tracked-body getter refreshes pose and velocity from the final qpos/qvel on the live per-world model, including reset randomization and fixed-variant rows; ctrl-only work and steps whose body state is never read do not pay that refresh. The four injected sensor blocks share one device-to-host transfer through buffers allocated during construction. This refresh does not re-run the constraint solver: named contact and force sensors continue to report values from the physics substep that was just completed.

`get_state()` snapshots on the MuJoCo and MJWarp adapters use each model's complete MuJoCo generalized-state layout (`nq` qpos columns and `nv` qvel columns). This is the same layout accepted by `set_state()` and addressed by named state and floating-root index APIs. Fixed-base models therefore contain no synthetic root columns, and a free joint elsewhere in the model stays at its native qpos/qvel position.

`get_joint_range()` returns the legacy joint-limit table when called without arguments. Passing `names` selects hinge or slide joints by name on the MuJoCo and MJWarp adapters, preserves request order, and returns `(N, 2)` position bounds in radians or meters respectively. Unknown and non-scalar joint names fail with `ValueError`; an unlimited scalar joint returns `[-inf, inf]`. Name-to-model mapping stays inside the adapter and is independent of qpos addresses.

`unisim-core` owns the public physics contract, backend capabilities, adapter factory boundary, engine-native resources, conformance checks, and the reserved benchmark case/result schemas. It has no dependency on UniLab, Hydra, Torch, Gymnasium, learner, runner, or task code.

UniLab owns task/env/manager lifecycle, Hydra owner YAML, robot assets, training, checkpoints, and sim2sim policy I/O. UniLab translates task-owned scene and randomization inputs into the UniSim contract.

Engine adapters are constructed with a package-neutral `SceneCfg` and an optional vectorized environment count. Model metadata is parsed only during construction; state and control arrays cross the public contract, and engine objects never escape an adapter. IsaacGym and IsaacSim share the subprocess IPC framing and keep their Python 3.8 and Kit workers outside the core wheel.

`unisim.ADAPTER_SPECS` is the single migration manifest for every declared UniLab backend identity. `available` means that a public adapter and diagnostics exist; it does not claim that a proprietary SDK or GPU runtime is installed on every host. Runtime support is established by the adapter's optional-extra and worker smoke tests.

All asset and model metadata resolution is a cold-path concern. Hot-path `step` and `reset` code receives validated arrays and cached identifiers; adapters must not dynamically probe private engine attributes.

Interval domain randomization is declarative: UniSim's manager builds `IntervalRandomizationPlan.ops` from `IntervalTermOp` descriptors defined in `unisim.dr.interval` (term name, NumPy payload, and optional body IDs; only the standard library and NumPy are used so plans remain pickle-safe across spawn-based collector processes). Each backend owns its capability declaration (`supported_interval_terms`) and a cold-path-built `_interval_term_handlers()` table; the generic `SimBackend.apply_interval_randomization` dispatch validates each op against the builtin term specs, routes it to the matching handler, and fails closed with `NotImplementedError` for any term the backend does not declare. Custom terms are free-form strings owned by the registering backend and are validated only against that backend's capability set.

Reset-time model-field writes use the curated fields on `ResetRandomizationPayload`; callers never submit compiler-derived fields such as geometry bounds independently. Adapters expose authoritative defaults through `SimBackend.get_reset_term_default(term)`: a canonical table for a single-model backend or a per-environment table when fixed variants establish different baselines. Default queries never change with reset randomization.

Body center-of-mass offsets (`body_ipos`, the COM position in each body's local frame, in meters) have two explicit query forms. `SimBackend.get_body_ipos()` without arguments returns the canonical model default table of shape `(nbody, 3)` in every mode; `get_body_ipos(env_ids=...)` returns the current effective per-environment values with shape `(len(env_ids), nbody, 3)` in `env_ids` order, reflecting every reset randomization applied so far (including composition with `base_com_offset`), and environments untouched by a partial reset keep their previous values. Indices must be a one-dimensional integer sequence; order, duplicates, and empty selections are preserved, while fractional, boolean, multidimensional, and out-of-range indices fail with `ValueError`. The MuJoCo and MJWarp adapters implement both forms; mapped IsaacSim implements the canonical form from its compiled source and the selected form from validated native materialization records, while its legacy model-file path fails closed.

Per-environment gravity is a first-class reset term on both the MuJoCo and MJWarp adapters. MJWarp tiles the per-world `opt.gravity` vector during the same cold-path expansion as its model fields; every consumer kernel indexes it by world, so a reset row write takes effect for that world's post-reset forward and persists until the next explicit update.

External body wrenches keep one lifecycle across wrench-capable adapters. `apply_body_force()` accepts an optional world-frame torque channel (force and torque act at the target body's center of mass, matching MuJoCo `xfrc_applied`), the `body_force` and `body_torque` interval terms share the same staging, submissions within one control step accumulate, and the staged wrench applies to every substep of the next `step()` call before being consumed. A later plan replaces an unconsumed one, and a partial reset clears only the reset worlds' staged rows. Mapped IsaacSim entity scenes implement this fixed interval lifecycle with IsaacLab external-wrench buffers and compose the dynamic callback wrench described below.

`SimBackend.set_pre_step_control()` converts policy control before every physics substep. A callback may additionally return a `PreStepControlOutput` carrying a dynamic body wrench: the wrench is recomposed from scratch each substep (it never accumulates across substeps or control steps), composes additively with the staged interval wrench, and both channels are cleared when the `step()` call finishes. Wrench-capable adapters refresh the tracked-body world state to the substep-start state inside the callback path — on MuJoCo this uses the mjbatch split-substep sensor copyout (`mjbatch-uni >= 0.2.1`, a hard executor requirement), which refreshes the tracked world-frame sensor views at every substep boundary at memcpy cost — and calling the interval/force staging APIs from inside a callback fails closed, so the callback must return its wrench instead. Ctrl-only adapters reject a wrench result with `NotImplementedError` rather than silently downgrading it to the `ctrl` component.

The callback paragraph above describes dynamic callback adapters. Mapped IsaacSim entity scenes support host callbacks by issuing one worker STEP per public physics substep and refreshing shared state before each callback; this is a correctness path, not the device-resident controller or performance path tracked by #152. Legacy IsaacSim model-file callbacks remain unsupported.

The MuJoCo factory option `refresh_pre_step_body_state` controls only that callback-time tracked-body refresh. Its default `True` preserves the contract above; passing `False` keeps the injected body sensors and body-state getters available, updates generalized state and dynamic wrenches at every substep, and leaves callback-time body-sensor views unfresh. This permits generalized-state controllers with the `implicitfast` integrator without accessing executor-private options.

On MJWarp, the callback loop remains on the host, but each post-upload physics substep replays the captured fixed-address step graph when capture is available; ineligible or failed captures retain eager kernel launches. Graph replay is an execution-scheduling optimization, not a promise of bit-identical eager output: short-horizon float32 comparisons must state their tolerance, while contact-heavy trajectories can amplify small execution-order differences.

After a MuJoCo control step returns, tracked-body getters are synchronized lazily with the final `qpos`/`qvel` of that step. Getters perform a host-side kinematics and velocity-sensor pass only for requested environment rows that still need synchronization, using one scratch `MjData` allocated during materialization and copying adjacent injected sensor blocks together. Partial reset and velocity updates clear only the affected rows' pending refresh; callback getters use the executor's copyout without duplicating host kinematics. Environments that do not request body tracking, steps whose body state is never read, and generalized-state-only reads pay no refresh cost. Authored sensors remain in native post-`mj_step` timing: acceleration-stage values such as contact forces keep the values solved by the last physical substep and are not replaced by a full final-state `mj_forward`.

If a pre-step callback raises, MuJoCo and MJWarp consume both staged and dynamic wrenches while retaining completed substeps. Public state remains readable for recovery; MJWarp also publishes elapsed time and the sensor cache for those completed substeps. Cleanup does not roll physics back or run a new force solve.

Fixed model identity is separate from reset randomization. A whole-model task carries `SceneCfg.fixed_variant_plan`; a portable entity scene carries the same plan through `SceneCfg.entity_variant`, whose catalog sources describe the bound target entity rather than the complete scene. Engine adapters realize the selected identity during construction, before their first forward and before CUDA graph capture. The plan contains final read-only assignment rows, complete materialized `ModelSourceDescriptor` entries, and a public layout guarantee (`same_layout` or `uniform_public_layout`). Domain-randomization capabilities advertise the layouts an adapter can realize and whether playback exposes a per-env model. The plan and capability objects use only standard-library and NumPy types, so they remain pickle-safe; live `MjSpec`, mjbatch, and Warp objects never cross this boundary. Slot merging, mesh/material pooling, per-world arrays, derived-field recomputation, and playback representation are adapter-owned implementation details.

The MuJoCo adapter realizes that contract without reintroducing one full model per environment. On the cold path it independently compiles each materialized MJCF as a numerical/default oracle, validates same or uniform public layout, and delegates canonical mesh pooling to mjbatch's `VariantPack`. For an entity binding, optional-slot validation covers the target entity and its explicit mirrors; unrelated scene geoms must remain stable but do not define target slots. `uniform_public_layout` permits only absent named mesh-geom slots, selects the max-geom realization (with the lower index winning ties) as canonical, pools the catalog meshes on that canonical source, and normalizes derived body semantics before constructing the pack. The adapter retains the canonical executor model, compiler-derived variant rows, compact default tables, and the immutable assignment rather than one compiled `MjModel` per variant. Runtime reset writes use the same expanded model-field views as canonical mode. Same-layout mesh-geom slots may be disabled per world, while changes to public state or control topology fail closed. Playback compiles a detached visual oracle on demand from the selected source, and offline playback saves one self-contained model per rendered environment.

The MJWarp adapter realizes the plan during construction. It streams every MJCF source through independent oracle compilation and validates the complete catalog against the final canonical layout, but retains compiler artifacts only for the canonical source and assignment-selected sources. It pools meshes and materials into one canonical model and installs per-world `geom_dataid`, `geom_matid`, and mesh-dependent model fields after `put_model` but before the first forward and CUDA-graph capture. Compact source-to-executor mappings preserve reset defaults, import reports, and playback identity, so reset mirrors and `get_reset_term_default()` start from each world's assigned variant.

The IsaacGym adapter realizes the same plan through actor-level asset selection. For a whole-model plan, the worker loads each complete MJCF source once with `gym.load_asset`; for an entity binding, the common compiler validates the complete portable catalog and exports its self-contained expanded sources and metadata for the target entity and its mirrors while unrelated entities stay canonical. Exported sources carry meshes, OBJ material libraries, and local texture maps beside the XML. The host computes worker initial rows one assigned full-scene realization at a time, and the worker retains native assets only for assignment-selected source rows. Both entry points use IsaacGym's global default ground plane. The worker validates public body and dof topology, creates every environment's actor from its immutable assignment row, and audits native asset identity; complete catalog identity remains available for playback and source mapping. `create_backend(..., isaacgym_env_spacing=...)` sets adjacent environment-origin spacing in meters (default 4.0); the host rejects worker spacing or native-origin grids that differ from the request. Per-variant actuator properties and task-initial keyframes are mapped by joint name, the handshake echoes the assignment, and native rendering already shows the assigned actor. Preview 4 does not preserve source visual materials, so IsaacGym applies a per-body color derived from the first visible source geom as a viewer-only fallback. Internal PhysX shape counts, including present versus absent optional mesh slots, may differ, but public state, action, sensor, dof, and body-layout drift fails closed. Reset-time model-field randomization remains undeclared and therefore unavailable on this adapter.

Physics-state playback rendering is a formal backend contract. A backend declaring `get_play_capabilities().supports_physics_state_playback` serves `get_physics_state()` snapshots whose rows use the `[time, qpos, qvel]` layout with an optional `[mocap_pos(nmocap*3), mocap_quat(nmocap*4)]` tail for models with mocap bodies. The layout is described at the contract level by `get_physics_state_layout()`, which returns a `PhysicsStateLayout` (`nq`, `nv`, `nmocap`); render frontends decode snapshots through `PhysicsStateLayout.split_state()` instead of hardcoding column slices. Recorded mocap body poses are exposed through the contract method `get_playback_mocap_state(env_index)`, declared with `supports_mocap_playback`, so interactive and offline renderers never touch backend-private state. `assert_backend_conformance` validates the contract on declaring backends: snapshot shape and layout agreement, playback-model loadability (an `MjModel` or a compilable MJCF/MJB file), a set/get round-trip when the backend overrides `set_physics_state`, and mocap-tail consistency with the declared capability. The MuJoCo, MJWarp, Newton, Drake, SuperDex, Motrix, and Genesis adapters implement the layout contract. Motrix accumulates snapshot time on the backend because its native scene data carries no simulation clock (`nsteps * sim_dt` per public step path, zeroed on full state resets), serves the whole-MJCF construction source or the composed portable MJCF as its playback model (fixed-variant scenes with multiple materialized sources require an explicit `env_index` and return the assigned variant file), and reports `nmocap=0` in this phase because kinematic mocap mirroring is not yet part of its snapshot tail. Genesis serves snapshots from its host qpos/qvel caches (Genesis free-base and ball-joint quaternions are natively wxyz) with the same backend time-accumulator semantics, validates the whole-MJCF native generalized-state order against the source MJCF joint order at materialize time (fail-closed, reusing the shared MJCF joint-layout inventory), replays through the fragment-expanded construction source or the composed portable MJCF (fixed-variant scenes follow the same explicit-`env_index` rule), and likewise reports `nmocap=0` while kinematic mirror mocap replay remains a follow-up.

The semantic boundary is documented in the [capability and evidence ADR](adr-capabilities.md), and portable scene authoring is documented in the [portable MJCF ADR](adr-portable-mjcf.md). SDK-free declarations, scoped evidence, cached import reports and explicit strict construction are independent of `AdapterSpec.status`; the [generated semantic inventory](support-matrix.md#semantic-inventory) describes source-reviewed subsets and unresolved features.
