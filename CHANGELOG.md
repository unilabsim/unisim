# Changelog

## Unreleased

- Added IsaacSim support for entity-bound `uniform_public_layout` fixed variants whose catalog omits optional mesh-geom slots per variant (for example headless entries of a uniform-public tool catalog). IsaacSim places every environment in one homogeneous PhysX view, so the mapped worker cannot realize subset variants structurally; instead, variant validation normalizes each subset record to the full public layout and marks the omitted slots, the role bake authors a tiny collision-disabled invisible placeholder sphere prim per omitted slot (contact/rest offsets baked, `unisim:geomIndex`/`unisim:geomName`/`unisim:placeholder` identity attributes pre-authored, and the placeholder slot list joins the bake parameters so the role USD cache identity tracks it), and native geometry authoring/readback now matches prims by those attributes instead of by child order. Role inspection re-validates cached placeholder prims fail-closed (collision must stay disabled), the host-side native-geometry audit accepts the resulting disabled placeholder rows only for environments whose assigned variant omits the slot — an enabled placeholder row or disagreement among slot-carrying environments still fails closed — and `_mapped_default_geom_friction` scatters subset variant rows into the padded public table by order-preserving name matching. Mapped DR capabilities now declare `uniform_public_layout` alongside `same_layout` plus per-environment playback when a variant plan is bound. Physics is unchanged: disabled-collision shapes produce no contacts and contribute no mass under the MJCF importer's explicit MassAPI authoring.

## 1.7.6 - 2026-09-24

- Fixed MJWarp uniform-public fixed-variant validation rejecting catalogs whose optional mesh slots change the compiler-derived `body_simple`/`dof_simplenum` flags: omitting the last optional mesh geom of a body (for example the headless entries of a uniform-public tool catalog) flips `body_simple` on that body relative to the canonical union model, and `dof_simplenum` follows it. Like the already-ignored `body_sameframe`/`geom_sameframe` flags, both are MuJoCo-CPU compiler diagnostics that the pinned mujoco-warp runtime does not consume as per-world Model fields, so they join `_IGNORED_COMPILER_FLAGS`; the eleven installed per-world variant fields and every other fail-closed shared-field check are unchanged.
- Fixed MJWarp composed-entity initialization rejecting uniform-public variant realizations whose per-variant scene models omit an optional mesh-geom slot. `_initialize_entities` required the full compiled scene layout — geom names included — to be identical across every variant file, which contradicts the optional-slot semantics the adapter itself declares; geom-stripped layouts already carry every qpos/qvel/ctrl address the default-state extraction below the check consumes, and `prepare_fixed_variants` still restricts omissions to optional mesh slots fail-closed. Same-layout catalogs keep the strict full-layout comparison.
- Implemented the physics-state playback contract (#291) on the Motrix adapter (#302). `MotrixBackend` now declares `supports_physics_state_playback` alongside its native renderer/video flags and serves `get_physics_state_layout()`, `get_physics_state()`, `set_physics_state()`, and `get_playback_model()` on both scene modes, so UniLab's detached MuJoCo (viser) replay no longer fail-closes for motrix. Because Motrix `SceneData` carries no simulation clock, the snapshot time column comes from a per-env backend accumulator advanced by `nsteps * sim_dt` on every public step path and zeroed on full state resets, mirroring the MuJoCo adapter's time semantics; free-base quaternions are converted to wxyz, and the whole-MJCF mode validates the native generalized-state order against the source MJCF joint order at construction (fail-closed). Playback models reuse loadable sources — the whole-MJCF construction source, the composed portable MJCF, or, for fixed-variant scenes with multiple materialized sources, the assigned per-env variant file (explicit `env_index` required, Drake-style). Kinematic mocap mirroring remains phase 2, so the layout reports `nmocap=0`.

## 1.7.5 - 2026-09-23

- Require `mjbatch-uni~=0.2.4`, which publishes the streaming `VariantPackBuilder` API consumed by the fixed-variant pool construction below (#280); earlier 0.2.x executors lack the builder and fail closed at capability probing, so the compatible-release pin now starts at 0.2.4. The UniSim CI/test baseline and documented platform support are unchanged.
- Extended the bounded IsaacSim PhysX solver configuration with `gpu_max_rigid_contact_count` and `gpu_max_rigid_patch_count` (factory: `isaacsim_gpu_max_rigid_contact_count`, `isaacsim_gpu_max_rigid_patch_count`) (#292). Both are validated as positive integers fail-closed before any worker spawn, re-validated from the INIT payload worker-side, and mapped onto IsaacLab's `PhysxCfg.gpu_max_rigid_contact_count`/`PhysxCfg.gpu_max_rigid_patch_count`, which size the PhysX GPU rigid contact and contact patch stream buffers — the IsaacLab defaults (2^23 contacts, 5·2^15 patches) overflow at large environment counts and kill training with a patch buffer overflow, while the SimToolReal reference configuration pins 2^24/2^23. Because IsaacLab flattens these into the PhysX simulation parameters (carb settings) with no USD attribute, both workers report the authored value in the versioned configuration report instead of an engine readback, and the host still strictly compares the reported value against the INIT request; the import report marks their provenance as unverified rather than claiming a readback. Unset values keep the engine defaults unchanged.
- Formalized the physics-state playback rendering contract (#291). `SimBackend` now exposes `get_physics_state_layout()`, returning a `PhysicsStateLayout` (`nq`, `nv`, `nmocap`) that describes the `get_physics_state()` snapshot columns (`[time, qpos, qvel]` plus the optional `[mocap_pos(nmocap*3), mocap_quat(nmocap*4)]` tail), and `PhysicsStateLayout.split_state()` decodes snapshots so render frontends no longer hardcode column slices. Recorded mocap poses moved onto the contract as `get_playback_mocap_state(env_index)` (previously an MJWarp-private adjunct consumed by its interactive playback), declared through the new `BackendPlayCapabilities.supports_mocap_playback` field, which is auto-published as the `play.mocap_playback` capability; `PhysicsStateLayout` and `PhysicsStateParts` are public `unisim` exports. The MuJoCo, MJWarp, Newton, Drake, and SuperDex adapters implement the layout contract, MuJoCo's snapshot mocap gating now shares one definition with its reported layout, and MJWarp interactive playback consumes only contract entry points. `assert_backend_conformance` now validates the playback contract on declaring backends: snapshot shape/layout agreement, playback-model loadability (`MjModel` or a compilable MJCF/MJB file), a set/get round-trip for backends overriding `set_physics_state`, and mocap-tail consistency with the declared capability.
- Sped up the Motrix allocating `get_body_state_w` getter by routing it through the same fused `SceneModel.get_link_states` selected-body read as `copy_body_state_w`, replacing the two full-link cache gathers (pose + velocity) with one native selected read; numerical parity with the cache-based per-channel getters is pinned for whole-MJCF and portable scenes. Added a behavioral Linux test that steps a `cpu_ids`-configured Motrix backend and verifies the native worker threads' `sched_getaffinity` masks are confined to the requested CPU block, complementing the existing mocked passthrough contract tests.
- Sped up mapped IsaacSim INIT offset authoring and environment row resolution at large environment counts (#284). Collision contact/rest offsets are now baked into the per-variant role USD artifacts (the role cache identity tracks them exactly and cache hits revalidate them fail-closed) instead of being authored per destination collision prim on the composed stage — 466,944 per-prim writes at 12,288 envs collapse into the bake — and native view rows resolve to environments in O(N) via the generated env_<i> path structure, byte-for-byte pinned against the former quadratic prefix scan. The legacy model-file worker path is unchanged.
- Sped up the mapped IsaacSim instance audit at large environment counts (#284). The audit's USD subtree checks (collision state, articulation root and self-collision, visual sphere radii, geometry records) now run on one representative environment per assigned variant — destinations of a variant are byte-identical Sdf.CopySpec copies with no per-environment authoring path — while per-environment variant identity, the batched PhysX view readbacks (masses, COMs, inertias, drive gains, joint types, metatype topology), and the host-side comparison still cover every environment; a representative failure falls back to a full per-environment scan before failing closed. Reported audit records are bit-identical to the per-env scan.
- Added `scripts/diagnostics/isaacsim_scene_parity.py`, the maintainer-runnable form of the bit-exact mapped-scene equivalence probe used to validate #283 (#284): `dump` captures worker INIT metadata (native audit records, init telemetry, environment origins) plus a deterministic zero-control rollout through the public host-to-worker path, and `diff` compares two dumps fail-closed (exact structure/audit/prim-count sections, fixed rollout tolerance). The mapped worker also now shares one change-listener toggle across the batched destination copies and the prototype scope removal of each entity, with the post-`CopySpec` xform op rewrite documented as intentionally byte-aligned with `Cloner.clone` output; parity evidence is bit-identical across the refactor.
- Added cold-path INIT telemetry to the mapped IsaacSim worker (#284). `init_sim` now times every sequential phase (kit startup, environment grid clone, per-entity raw-USD cache/convert, role bake/inspect, prototype authoring, batched copy, prototype scope removal, entity totals, collision filtering, collision offsets, sim reset, map build, commit, audit) with `perf_counter`, snapshots per-phase RSS and stage prim counts at structural boundaries, and reports the ordered spans plus peak RSS and VRAM in `get_meta()` under the additive `init_telemetry` key, returned with the INIT response and `GET_META`. Step/reset hot paths never touch the recorder; legacy model-file scenes keep their metadata shape unchanged.
- Sped up mapped IsaacSim scene initialization for variant-heavy scenes (#281). Per-entity destination copies of the K variant prototypes previously ran as K independent `Cloner.clone` calls, each paying a fixed change-listener disable/enable pair and an `Sdf.ChangeBlock` flush, so clone time scaled with the prototype count regardless of how many destinations each prototype had. The copies of one entity now run under a single listener toggle and one change block through a worker helper that replicates the `copy_from_source=True` per-destination work exactly: the source xform ops collapse to translate/orient/scale, every destination receives a full `Sdf.CopySpec` into the stage root layer, and each destination keeps the source's local-to-parent transform (the same pattern IsaacLab's `MultiUsdFileCfg` spawner uses), and each entity's prototype scope is now removed with `Stage.RemovePrim` once its destinations are copied instead of staying resident as deactivated prims — deactivated prototypes kept every prim on the stage, and the growing stage made each subsequent copy slower (superlinear INIT beyond ~10k envs). Prototype authoring, assignment grouping, collision filtering, the sim reset, and the native instance audit are unchanged; a K=12 × N=64 scene dump (composed destination transforms, prim hierarchy, PhysX view order, mass/inertia readback) and a 50-step zero-action rollout are bit-identical between the per-call and batched paths.
- Fixed MuJoCo fixed-variant pool construction memory scaling (#280). `_load_fixed_variant_build` now streams every variant realization — one transient spec/model at a time — into the new mjbatch `VariantPackBuilder`, which retains only small compiler-derived per-variant rows and re-materializes just the canonical variant. Previously every assigned variant's compiled `MjSpec` (each embedding the full mesh payload, ~33MB on a 1200-variant SAME_LAYOUT entity pool) plus one compiled model per selected variant stayed resident, and `VariantPack.from_specs` compiled the whole set again internally, OOMing a 60GB host at 1200 variants × 2048 envs; the same pool now builds with a ~1.7GB peak. Validation order, import reports, reset defaults, the uniform-public `body.simple` hint sequence, and the executor `VariantPack` payload are unchanged; mjbatch-uni releases without the builder API fail closed at capability probing.
- Fixed the Genesis MJCF contact-sensor scan rejecting `<contact data="found" num="1" reduce="mindist"/>` (compiled intprm `(1, 1, 1)`): the scalar found flag ignores the reduce mode entirely, so the mindist-compiled form is now accepted as the same geom-pair found plan as reduce `none`. This restores scenes such as the UniLab G1 flat scene, whose eight foot geom-pair found sensors failed closed at backend initialization.
- Sped up multi-variant scene composition for subprocess (IsaacGym/IsaacSim) backends. `compose_scene` now caches the parse/compile/provenance of variant-invariant entities (previously re-parsed and re-compiled once per catalog variant), reuses already-parsed namespaced variant specs for the uniform mesh-catalog merge, captures each variant's initial state from the already-compiled serialized realization, and drops the redundant pre-serialization recompile after keyframe merging; worker scene preparation reuses those captured initial-state snapshots instead of recompiling every variant file, and the host entity configuration report resolves variant→environment rows in O(N) instead of O(variants×envs). Compiled artifacts, provenance, content identity, and all fail-closed validations are unchanged.
- Added dependency-free terminal progress reporting for long cold-path builds: multi-variant scene composition, worker-source export, and IsaacGym worker initialization (asset loading and per-environment actor construction, delivered as host-requested interleaved `PROGRESS` protocol frames that also re-arm the host INIT timeout) render a single-line stderr progress bar. Output follows terminal detection and is controlled by the `UNISIM_PROGRESS` environment variable (`auto` default, `always`/`1`/`on`/`true` to force, `never`/`0`/`off`/`false` to disable). The IsaacGym worker also queries per-asset DoF/body name tables once per materialized source instead of once per actor.
- Parallelized multi-variant scene composition across processes. MuJoCo compilation holds the GIL, so `compose_scene` now fans independent per-variant realizations out to a `fork`-context process pool (spawn fallback on platforms without fork) once a binding declares at least 16 variants; the declared-base bootstrap realization and every cross-variant fail-closed check still run in the calling process, in variant order, and generated sources are byte-identical to sequential composition (asset `content_type` hints are stripped from serialization because `to_xml()` resolves them through the timing-dependent process-global asset cache). Worker count follows `UNISIM_COMPOSE_WORKERS` (default `min(24, cpu_count)`, `1` disables pooling). A 1200-variant uniform catalog build drops from roughly two minutes of single-threaded compilation to near-linear parallel scaling.

## 1.7.4 - 2026-09-21

- Added Motrix worker CPU affinity (#234, downstream driver: UniLab #962). The factory and `MotrixBackend` accept an optional cold-path `cpu_ids` block validated with the MuJoCo `BatchEnvPool` affinity contract (non-empty, unique, non-negative, available to the process); when set, the adapter initializes MotrixSim's shared Rayon pool via `motrixsim.init_thread_pool(core_ids=...)` before the first model load, pinning worker `i` to `cpu_ids[i % len(cpu_ids)]`, and exposes the validated block through the read-only `cpu_ids` property. An already-initialized shared pool degrades to a warning instead of failing env construction, and the default path leaves the pool untouched. Requires `motrixsim-core==0.10.1`, which this release pins.
- Sped up Motrix `copy_body_state_w` by routing it through the fused `SceneModel.get_link_states` selected-body read from MotrixSim Core 0.10.1 (#237, downstream driver: UniLab #1305/#1308). One native call gathers position, wxyz quaternion, linear and angular velocity for exactly the selected links — no full-link Python intermediates — writing caller-owned float32 C-contiguous buffers directly, with a packed-read-plus-cast fallback preserving the dtype-agnostic contract for other buffers. Portable scenes copy per runtime with a contiguous-row-block fast path. Parity with the cache-based getters (body order, wxyz order, dtype, repeated caller-owned buffer reuse) is pinned for whole-MJCF and portable scenes.
- Added MuJoCo opt-in selected-body tracking sensors. `create_backend(..., body_state_required=True, tracked_body_names=...)` (or the corresponding direct MuJoCo constructor option) narrows cold-path sensor injection to exact named bodies while preserving the all-named-bodies default. Invalid inputs, use without body-state sensors, non-MuJoCo factory requests, and getters for omitted model bodies fail closed.
- Fixed the mapped IsaacGym worker passing integer environment indices where the Preview 4 bindings require native `Env` handles; reset randomization and its property readback/audit now resolve `ctx.env_handles` before every per-actor Gym call, restoring the native `get_actor_asset`/DoF/rigid-body/rigid-shape accessors (#272).
- Fixed IsaacGym interval body wrenches reading freed GPU memory: `gymtorch.unwrap_tensor` only borrows the Torch storage pointer, so the worker now retains the force/torque Torch tensors for the lifetime of the staged wrench instead of dropping the temporaries at return (#272).
- Fixed IsaacGym reset `body_ipos` randomization on the GPU pipeline: PhysX honors rigid-body COM writes physically, but Preview 4's rigid-body property readback keeps the pre-write COM, so the worker now substitutes the requested offsets on selected rows before the readback audit and COM-cache commit (unselected rows and every other field keep their native audit) (#272).
- Added per-entity self-collision for mapped IsaacGym entity scenes (#265). `SceneEntitySpec.self_collision=True` is honored through PhysX collision filter authoring: the actor spawns with a zero collision filter (PhysX suppresses a pair exactly when the two shapes' filter words share a bit) and the worker assigns one distinct per-shape filter bit to every collision-shaped body through the rigid shape properties, verified by native shape-property readback — IsaacGym offers no actor-level filter readback, so honoring is enforced at authoring. Other physical entities keep the per-entity bit scheme bit-identical, and collision-disabled actors (including mirrors) carry the union of every allocated bit and stay excluded from self-collision bodies. Authored `<contact><exclude>` pairs on a self-collision entity cannot be expressed without per-pair bit coloring and fail closed at worker validation, as do requests on rigid entities or mirrors and scenes whose entity plus per-body bits exceed the 30-bit filter budget; directly joint-connected link pairs never collide in PhysX regardless. The worker reports the effective flag and body-bit assignment per entity in the versioned configuration report, and the host strictly compares that report against the INIT request. The IsaacGym `collision.self` capability is now a conditional exact declaration (`entity.self_collision=true`, `scene.profile=mapped_entities`); legacy model-file scenes keep self-collision disabled. Validated natively: a self-overlapping three-link chain develops net contact force on its bodies only when the flag is enabled.
- Extended the bounded IsaacSim PhysX solver configuration with `rest_offset` and `max_depenetration_velocity` (factory: `isaacsim_rest_offset`, `isaacsim_max_depenetration_velocity`) (#265). The rest offset is validated against the PhysX `rest_offset <= contact_offset` requirement — an explicit contact offset is required alongside it — and both workers author it on every collision shape through `PhysxCollisionAPI` alongside the contact offset. PhysX 5 expresses the depenetration velocity cap per rigid body (the bundled PhysX schema has no scene-level attribute), so the workers author it on every rigid body through `PhysxRigidBodyAPI`, mirroring the IsaacGym `sim_params.physx.max_depenetration_velocity` semantics. Both values join the versioned configuration report as USD-stage engine readback with the same strict host request-versus-readback comparison; unset values keep the engine defaults unchanged.
- Added per-entity gravity disable for mapped IsaacSim and IsaacGym entity scenes. `SceneEntitySpec.gravity_disabled` (default `None`) preserves each backend's implicit per-entity behavior — IsaacSim disables gravity for kinematic entities and fixed rigid bodies, IsaacGym keeps gravity enabled on every entity asset — while an explicit `True`/`False` must be honored exactly or rejected, never ignored. The host resolves unset requests into the worker entity record before INIT; the IsaacSim worker bakes `physxRigidBody:disableGravity` from the resolved value and re-validates it on every baked or cached role, and the IsaacGym worker sets per-entity `AssetOptions.disable_gravity` at asset authoring (IsaacGym exposes no per-actor gravity readback, so honoring is enforced at authoring time). Both workers report the resolved flag per entity in the versioned configuration report and both hosts strictly compare that report against the INIT request. The new `entity.gravity_disable` capability is a conditional exact declaration for both Isaac adapters (`entity.gravity_disabled=explicit`, `scene.profile=mapped_entities`); MuJoCo/MJWarp declare it unsupported and every other backend fails closed on an explicit request at the composition negotiation boundary (#265).
- Added IsaacGym mapped-scene `get_reset_term_default()` tables. The eight declared mapped reset terms (`kp`, `kd`, `body_mass`, `body_ipos`, `body_inertia`, `dof_armature`, `dof_frictionloss`, `geom_friction`) now serve authoritative per-environment default tables derived from the frozen scene layout records and each environment's assigned variant, matching the IsaacSim semantics: entity-owned columns scatter the variant-authored values, unowned body columns keep the compiled canonical table, geom friction serves Coulomb `static == dynamic` pairs with a zero third column, and results are detached read-only `float32` arrays. Unknown terms, declared-but-unsupported terms, malformed compiled variant records, and the legacy model-file path fail closed (#265).

## 1.7.3 - 2026-09-20

- Added bounded Motrix support for `uniform_public_layout` fixed variants with complete mesh slots on MotrixSim Core 0.10.1. The adapter builds one canonical native model/data context, binds audited public mesh geoms to native per-row mesh variant sets, verifies exact ordinal readback across reset and steps, preserves same-layout per-variant execution, and declares per-environment native playback with renderer identity and offset evidence; absent optional mesh slots and non-mesh source differences fail closed (#266).
- Added IsaacSim per-body net contact force and found-flag contact fragments on mapped scenes. Portable sensor fragments may now declare `<contact data="force" reduce="netforce">` and `<contact data="found">` with `geom2` omitted (wildcard over every contact counterpart); the mapped IsaacSim worker binds the owning entity's bodies through exact-path raw PhysX rigid-contact views, re-enables PhysX contact processing when either contact form is present, and polls the views on every physics substep because PhysX GPU zeroes a body's entry only on the exact step where contact is lost (lazy reads would pin the last in-contact force). PhysX reports world-frame normal-only forces acting on the authored body — the opposite sign convention of MuJoCo's geom1-exerted force — with self-collision disabled; selected resets clear all mapped contact rows until the next completed step, and legacy whole-model scenes keep failing closed. IsaacGym serves the same wildcard forms from its per-body net-contact tensor, and the support matrix documents both (#249).
- Added a bounded, fail-closed PhysX solver configuration for the IsaacSim backend (#251). Construction accepts `solver_position_iteration_count`, `solver_velocity_iteration_count`, `bounce_threshold_velocity` and `contact_offset` (the factory exposes the same options with the `isaacsim_` prefix); both the legacy and mapped workers map iteration counts onto the PhysX scene min/max range and the bounce threshold onto IsaacLab's `PhysxCfg`, author a uniform contact offset on every collision shape, and report the applied values as engine readback in the versioned configuration report while the host strictly compares request against readback. The settings stay out of the raw/role USD cache identities, and SimToolReal-style substeps remain expressed as `step(ctrl, nsteps)` decimation rather than a new solver knob.
- Added bounded IsaacSim mapped-scene per-environment reset domain randomization. Selected `set_state()` rows now accept actuator `kp`/`kd` drive gains, `body_mass`/`body_ipos`/`body_inertia` (with `base_mass_delta`/`base_com_offset` folded host-side into the primary entity's root body), and nonnegative `dof_damping`/`dof_armature`/`dof_frictionloss` joint tables alongside the existing `geom_friction` writes; every write goes through the mapped public PhysX views, is read back natively, and is verified against the request and the untouched rows before the reset barrier returns. Fixed-variant plans may now carry per-variant drive stiffness/damping: initialization rewrites each environment's assigned variant gains through per-row view setters, and mapped DR capabilities declare `supports_fixed_variants` with the `same_layout` guarantee plus per-environment `get_reset_term_default()` tables. The static `root.fixed` declaration for mapped IsaacSim scenes is now exact. Gravity, inertial orientation, geometry dimensions and solver contact parameters remain fail-closed with explicit per-term reasons (#248).
- Added per-entity self-collision for mapped IsaacSim entity scenes. `SceneEntitySpec.self_collision` (default `False`, preserving existing behavior) is validated as a collision-enabled physical articulation request, forwarded in the worker entity record, and applied through the MJCF converter with the raw-USD cache identity and actual conversion parameters kept in sync. The imported `physxArticulation:enabledSelfCollisions` flag is verified during role baking, explicitly re-authored when fixed roots move the PhysX articulation API to the root prim, audited on every spawned instance, reported per entity in the versioned configuration report, and strictly compared against the INIT request on the host. Authored MJCF `<contact><exclude>` pairs remain excluded as USD filtered pairs independently of the flag. The IsaacSim `collision.self` capability is now a conditional exact declaration (`entity.self_collision=true`, `scene.profile=mapped_entities`); MuJoCo/MJWarp declare exact source-authored retention (`entity.self_collision=authored`), and every other backend — including IsaacGym, whose worker disables self-collision globally — fails closed on `self_collision=True` at the composition negotiation boundary and in `compose_scene`. Contact-pair and body-net contact declarations on a self-collision-enabled entity also fail closed, so reported contact forces never mix in self-contacts (#251).
- Added bounded IsaacGym mapped-scene reset domain randomization. Selected `set_state()` rows now accept actuator `kp`/`kd`, `body_mass`, `body_ipos`, `body_inertia` (principal triples composed with the assigned variant's inertial orientation), `dof_armature`, `dof_frictionloss` and Coulomb `geom_friction`; the host prevalidates public columns, the mapped worker applies mutations ahead of the staged state write, and native readback audits selected-row correctness plus unselected-row isolation before the verified records refresh the COM caches. `gravity`, `dof_damping`, base mass/COM deltas, inertial orientation, geometry sizes and solver parameters fail closed, as does the legacy model-file path (#255).
- Added IsaacGym mapped-scene world-frame `body_force`/`body_torque` interval wrenches. The host stages a `(num_envs, nbody, 6)` table, the worker scatters it into env-local `ENV_SPACE` force/torque tensors, and re-applies them before every requested substep because PhysX consumes external forces at each simulate call (#255).
- Converged the IsaacGym `root.fixed` declaration from `unknown` to `exact` under the mapped MJCF profile; fixed-root reset writes remain fail-closed per contract (#255).
- Require `mjbatch-uni~=0.2.3`, which fixes VariantPack compiler-derived flags no longer being treated as shared skeleton parameters and adds prebuilt Windows wheels. The UniSim CI/test baseline and documented platform support are unchanged in this release.
- Fixed MuJoCo uniform-public catalog memory scaling. Scene composition and backend validation now stream full-scene realizations, retain only canonical and assignment-selected executor artifacts, lazily rebuild variant layouts, and continue validating the complete catalog fail-closed (#245).
- Fixed IsaacGym entity-bound uniform-public catalog memory scaling. Host initial-state preparation now streams assigned full-scene realizations, the mapped worker retains only assignment-selected native assets, and complete catalog validation plus playback/source identity remain fail-closed (#250).
- Fixed MJWarp uniform-public catalog memory scaling. Variant materialization now retains only canonical and assignment-selected compiler artifacts while transiently validating the complete catalog, and compact executor mappings preserve reset defaults, import reports, and per-environment playback identity (#253).

## 1.6.0 - 2026-09-17

- MuJoCo tracked-body state now uses mjbatch's native selective `refresh_sensor_ranges` worker path when available, replacing the per-environment Python/ctypes kinematics loop after normal steps. The refresh copies only injected tracking sensor columns, preserving last-substep acceleration/contact sensors and other bound fields; older executors retain the host fallback.
- Removed transient milestone evidence JSON and per-PR audit pages from the documentation tree. The five entity-runtime implementation notes were consolidated into one bilingual page, and the durable design decisions now use semantic filenames instead of milestone labels.
- Optimized the #141 legacy IsaacGym FK path after a bounded A/B ablation. The host now parses each MJCF source once while collecting both metadata and kinematic-tree tables, and the worker validates/converts FK wire tables once during adoption instead of on every reset. Fixed-variant row grouping uses NumPy indices while retaining sparse per-environment overlay storage. The ablation rejected an always-allocated dense overlay buffer because it traded sparse reset memory for no reliable refresh gain.
- Fixed stale post-reset body state on the legacy IsaacGym subprocess path (unilabsim/unisim#141). PhysX does not refresh rigid-body link poses until the first `simulate`, so after INIT keyframes and every `set_state` the worker published the spawn-time rigid-body tensor (a standing G1 read `left_ankle_roll_link` at z=-0.107, and readbacks jumped by physically impossible amounts per control step), which terminated motion-tracking episodes after 1-2 steps. The host now scans the MJCF kinematic tree (`scan_scene_kinematics` in `subprocess_ipc.sensors`) into the INIT payload — per variant under fixed variants — and the IsaacGym worker overlays exact MuJoCo-semantics forward kinematics (positions, orientations, link-origin linear and world angular velocities) onto freshly written environments until the first physics step, clearing their stale contact-force rows as well. The overlay composes partial reset masks against the current slot state, is bound per fixed-variant assignment, and fails closed when the payload does not match the adopted public body/joint layout; importers that reorder bodies or joints keep the existing fail-closed behavior. The scan rejects MJCF constructs the kernel does not implement (ball or compound joints, non-`quat` body orientations, nonzero joint `ref`, multiple or nested free joints). Fixed-base legacy assets without a freejoint keep publishing native rows. The isaacsim legacy path already published correct post-reset body state since 1.5.0 (#109); a native regression test now pins that behavior.
- Fixed a root-velocity convention mismatch on the legacy subprocess reset input (#141). The canonical host writes `set_state` qvel verbatim (world link-origin linear velocity plus body-frame angular velocity, per the `SimBackend.set_state` contract), but the IsaacGym legacy reset codec subtracted a root COM correction intended for the historical Gym wire, corrupting the uploaded root velocity and every derived body velocity by `omega x root_com` whenever the root angular velocity was nonzero. The codec now treats reset input as canonical; only the published legacy output buffers retain the historical COM-velocity projection.
- Added opt-in Newton CUDA graph execution (`use_cuda_graph` direct constructor option or `newton_use_cuda_graph` factory option). Capture follows cold-path capacity calibration, records both state-parity transitions, requires CUDA driver 12.4+ with mempool enabled, and falls back to eager execution with a diagnostic warning when ineligible or capture fails. Graph replay is callback-free; reset and pre-step control paths remain eager. Real CUDA tests cover eager/graph parity for odd and even substep counts, repeated replays, callback fallback, and selected-state reset followed by replay (Motphys/UniLab#1604).
